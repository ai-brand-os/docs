## Classification and closure protocol

A = blocking **before implementing the affected deterministic storage/policy choice**, not before all code can be written. B = component can be implemented/tested in isolation, but cannot be connected/enabled for that behavior before disposition. C = blocks public launch **and earlier controlled use of real customer data/paid pilot where stated**. D = deferrable for first slice/proposed writer, not permission to drop approved full-MVP functionality. E = superseded/duplicate only with actual decision evidence; **none of the52 pending decisions has evidence supporting E**. Six historical/directed records are retained separately below. Parent D-AUD decisions coordinate subgates and are not duplicate approvals.

P0=A/B affected first-slice path; P1=C before real data/pilot/claims; P2=D. Some records combine several branches: first applicable gate wins for the enabled branch, while stated disabled branches remain out. Developing a test adapter is not authorization to deploy the proposed production behavior. Every actual approval needs named identity/role, selected option, exact Git/schema/app revision, date, evidence and remaining scope limits. No deadline or approval is fabricated.

Close decisions in three review packets, not52 new ADRs: (1) storage/atomicity/auth choice A; (2) slice contract/privacy/configuration/Frontend binding B, including Founder import choices; (3) customer-data/operations/commercial C. Reviewers may approve narrower slice adoption with disabled optional branches. Record dispositions in the existing register and then implement; D items stay visibly deferred, not fake-closed. No response means no approval.
