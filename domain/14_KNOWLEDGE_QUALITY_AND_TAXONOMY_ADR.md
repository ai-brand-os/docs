## Region, language and standards

PrimaryRegion means Owner-confirmed market description. It is neither headquarters address nor country list, UI locale, provider processing region or output language. Multiple areas may be expressed in that single text description; no multi-market management feature. PrimaryLanguage means one Owner-confirmed business output language preference, not inferred from document text. Formatting locale affects display only; locale is not evidence of currency/date intent. Source language metadata may describe several detected languages without adding multi-language output workflows.

Use [ISO3166 country identifiers](https://www.iso.org/iso-3166-country-codes.html) only for explicit country semantics; use [RFC5646 / BCP47](https://www.rfc-editor.org/rfc/rfc5646.html) with the [IANA registry](https://www.iana.org/assignments/language-subtag-registry/language-subtag-registry) for language/locale tags. References consulted2026-10-19. Exact deployment registry snapshot, digest and supported output tags require D-KQ-02 review. Offline standards fixtures are deliberately a small representative profile, **not a full ISO/IANA registry or approved product allowlist**. They test lookup/casing/alias/unknown behavior; full standards conformance requires actual pinned registry integration.

Country canonical storage is uppercase assigned alpha2; deprecated aliases need an explicit reviewed map, no guessed UK→GB or country-name parsing. Language canonical casing is registry-defined (language lowercase, script titlecase, region uppercase); deprecated tags use exact pinned Preferred-Value mappings. Never normalize underscores/ambiguous names into approved tags automatically. Unknown future codes are unsupported/unknown, not Other. Well-formed but unregistered language tags are not accepted merely by regex or Intl syntax. Private-use/extensions/und/mul and unsupported output tags require an explicit product profile; proposed primaryLanguage excludes them by default. Source detection may retain und/mul as honest metadata under its own existing contract. Historical English/region strings remain historical; conversion to a new tag or market interpretation requires Owner confirmation/new revision. Display labels localize separately and never become stable identifiers. Unicode trimming does not translate/transliterate business meaning.

## Indicator ownership, formula and missing values

[Quality package1.0](../contracts/knowledge-quality/README.md) owns exact schemas, registries and reference algorithms. All candidate numeric formulas are **disabled pending review**, monitoring/review aids only. No weights/thresholds are empirically calibrated.

- Extraction owns EXTRACTION_CONFIDENCE: four equal procedural checks `literalPreserved`, `classificationValid`, `parseUnambiguous`, `sourceBindingResolved`. PASS/FAIL must be established from actual typed candidate, parser and Source Evidence references; not copied from model self-rating. Unknown/unavailable checks make score UNKNOWN/UNAVAILABLE. Explicit NOT_APPLICABLE excludes a check with reason; zero applicable checks is NOT_APPLICABLE, never100. Provider/detector self-ratings keep their original method/range as untrusted source metadata if their existing contract allows, otherwise omit; never relabel them as this formula. Manual facts have no extraction score.
- KM owns KNOWLEDGE_CONFIDENCE: four equal support checks `supportResolved`, `interpretationResolved`, `verificationCurrent`, `sourcePolicyAcceptable`. These describe documented support, not probability of truth. Source policy is a separately reviewed categorical assessment; no recursive Knowledge→Source score. Manual support is actual author/input provenance, not a fabricated Document; source policy may be NOT_APPLICABLE. Verification uses explicit pinned verified/due/as-of records, not automatic bonus for fact approval. Currency/date ambiguity makes interpretationResolved FAIL and triggers existing blocking/correction policy independently of score.
- Evidence quality remains Source Evidence categorical fidelity; live byte availability is separate. Missing original offset may yield STRUCTURAL/NORMALIZED_ONLY or warning, not zero accuracy/false fact. INVALID digest/forged source is a deterministic validation failure. Category is not numerically converted into factual accuracy. Derived support check outcomes must preserve original category/reasons and source-policy decision refs.
- Source Trust is categorical policy assessment with reviewer/policy/version/source reference: ACCEPTED_FOR_USE permits that source under policy, REVIEW_REQUIRED/REJECTED warn/block as existing governance requires, UNASSESSED means no assessment. Owner fact approval does not manufacture this source-policy review or factual truth. Numeric legacy sourceTrustScore remains {value:null,basis:null}; no new static trust percentages.
- Context owns CONTEXT_QUALITY, specifically a **required-context coverage proxy**. Input is a versioned, server-produced request manifest of required fact refs (registered task profile or baseline mandatory fields/selected complete offer and Audience) and actual eligible selected refs from one approved revision. Deduplicate exact typed fact refs; numerator=intersection, denominator=nonempty required refs. A manifested missing fact reduces coverage but readiness still blocks mandatory omissions. No manifest/unknown task requirements => UNKNOWN; zero required inputs => NOT_APPLICABLE. New task-intent classifiers/profiles are not silently authorized. High coverage is not response correctness.

For check scores: value=roundHalfUp(100×PASS/applicable), with exact rational integer arithmetic, integer0–100, no hidden coefficients. FAIL is known failure, not missing. An invalid check/weight/input fails validation. No custom weights accepted. An NA check requires an explicit trusted reason, cannot be selected merely to improve score. Entity projection is minimum of known field scores; if any applicable material field is non-KNOWN, do not emit the entity numeric index. Scores never average separate interpretations, approval or completeness. SourceTrust/Evidence categories have no numeric formula.

States: **KNOWN** has validated numeric/category value only; **UNKNOWN** means attempted but insufficient information; **NOT_EVALUATED** means disabled/not yet assessed; **UNAVAILABLE** means required input inaccessible; **NOT_APPLICABLE** means no relevant assessment; **INVALID** means malformed/inconsistent/tampered data. All five non-KNOWN numeric states require value=null and nonempty reasons; KNOWN numeric result may legitimately be0. Absent required fields are schema errors, not null. INVALID/raw NaN/Infinity/range errors are rejected before persistence; a sanitized diagnostic may record INVALID without unsafe raw data. For mixed unresolved checks precedence is INVALID > UNAVAILABLE > UNKNOWN; disabled formula yields NOT_EVALUATED before using inputs. No applicable checks yields NOT_APPLICABLE. Missing required keys are INVALID input, explicit unknown statuses preserve UNKNOWN.

Record indicator, formula/input versions, scope/subject/pinned revision, calculatedAt/asOf, exact normalized inputs, reasons and passed/failed/excluded counts. `inputHash` is SHA256 of stable-json-v1 canonical input+scope+subject+taxonomy/formula-set/formula/input versions+asOf; arrays have documented ordering. `resultHash` binds the whole result/explanation excluding itself. Recompute both and arithmetic for replay; hashes provide consistency, **not signatures or authorization**. Store inputs/references in restricted artifacts, not content logs. A quality assessment must load trusted actual subject/source/approval refs; clients/model cannot assert check PASS, policyReviewed, revision or source trust.

Recalculate on explicit candidate edit, selected source/binding change/availability check, approved fact/verification revision, policy/formula or request-manifest change. Retain old evaluation unchanged; new input/version produces new append-only assessment. No scheduled freshness monitor, automatic learning or model training. Exact replay uses recorded input/asOf/versions; current reassessment does not overwrite historical approval or score.

## Context ranking, quality and safe fallback

Proposed rank/1.0.0: filter unauthorized/unapproved/invalid/wrong-revision/current-deleted facts first; apply existing active complete member/readiness/source policies. Sort lexicographically by required-manifest membership descending, explicit requested-entity membership descending, distinct literal query-token matches descending, then typed `(entityType,entityId,fieldPath,valueRevisionId)` UTF8 byte ordering ascending. Tokens are pinned NFKC/lowercase Unicode letter/digit runs; this is literal keyword matching, not semantic relevance or multilingual NLP. Unicode/normalization implementation must be version-pinned for deployment. Missing query/profile uses zero match/empty manifest and stable identity order, not invented semantic scores. Candidate data is never a fallback.

Reliability indicators remain visible separate warnings. Freshness derives only from explicit due/as-of or observed source changes, not a ranking decay coefficient. Diversity can report distinct selected entity types, no claim more types improves quality. Business priority has no supported arbitrary field/weight, so no boost; required profile slots are explicit structural priority. Semantic similarity/vector relevance remains later evaluated architecture. Compression quality is NOT_EVALUATED without reproducible evaluator; MVP selects whole approved facts/refs, deduplicates and omits lower-ranked whole items within reviewed budgets, never summarizes away prices/negations or claims meaning-preserving compression was measured. Token budget/traversal limits still require existing owners; no new deployment budget approval.

Pin required/selected facts and Task20 relationship refs to one approved Artifact/BrandBrainRevision; relationships do not count as fabricated fact slots. Current auth/Brand/readiness/deletion/source policy/security remain hard gates independent of scores. No valid approved context => typed safe failure/refusal/request-for-required-knowledge via existing Context/Workspace paths, never generic fabricated grounding. Partial approved Brand Brief remains allowed under its existing limitation policy; it is not a generation-readiness bypass. Context score is for monitoring, no activation threshold or new customer dashboard.
