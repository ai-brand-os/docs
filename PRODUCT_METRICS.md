# Product Metrics and Generation Readiness

Effective contract: 2026-10-13. Status: proposed measurement/acceptance design, not implemented analytics or observed performance. All numeric targets are goals. Product scope: [MVP_SCOPE.md](MVP_SCOPE.md); knowledge/versioning: [KNOWLEDGE_PROVENANCE.md](KNOWLEDGE_PROVENANCE.md); retention: [DATA_LIFECYCLE.md](DATA_LIFECYCLE.md).

## Time to first value (TTFV)

**Definition:** elapsed wall-clock time from onboarding start to the first usable output grounded in approved Brand Brain information. Proposed goals: **median ≤10 minutes and p90 ≤15 minutes**. These are distribution goals, not a maximum for every user and not an observed result. Form completion, account creation, import success, a 70-point score, generation submission, first streamed token or a response without approved context does not constitute first value.

Start: OnboardingStarted is recorded by the server when a new eligible Owner first enters the initial Brand Brain setup flow and the setup form is made available. The event identifies the business onboarding instance, account/Organization/Brand and start time. If Brand is not created yet, attach it later to the same instance. Signup/login before entering setup is outside the clock. Repeated entry, refresh, device changes, import retries and resumed sessions retain the original startedAt; no artificial restart for a faster result. Only initial single-business onboarding enters this cohort; historical users editing an existing approved Brain are a separate retention cohort.

Stop: the first validated OutputPresented event for a successfully completed, nonempty, readable output grounded in approved Brand Brain facts. A qualifying output is a Workspace response with nonempty approved business context and successful structural/grounding response validation, or an approved Brand Brief assembled without invented facts. Both pin an approved revision and identify supporting approved fact keys. A partial approved Brief may qualify while generation readiness is false if its limited scope is visible. This uses a defined observable proxy for “usable,” not proof of external business impact or perfect factual accuracy.

Blank/error/refusal/placeholder/test/template outputs and outputs with no valid approved business facts do not qualify. Brand Brief at 0 with no approved facts is an empty guide. A first streamed token, model completion before delivery, import success or model success without grounding is insufficient. Server validation verifies the tenant-scoped output and pinned approved context, not a browser assertion. If validation/presentation fails, the clock continues. Helpful feedback, explicit usability confirmation and successful copy are supplementary quality/use signals; they are not required to stop TTFV and cannot backdate or overwrite the first presented qualifying output.

Use authoritative server start/qualification timestamps in UTC; stop is the server receipt/validation time of the complete output-presentation acknowledgement, including delivery latency. Delayed offline presentation events cannot retroactively claim a shorter time without a separately versioned clock-validation contract. TTFV = qualifiedAt − startedAt, in milliseconds; reject negative/mismatched-instance intervals as instrumentation defects, not zero-time wins. All waiting, idle time, manual edits, network/provider failures, user pauses and retry time after start are included.

## Cohorts, exclusions and abandoned sessions

Use one initial onboarding instance per business/account, independent of browser sessionId. Proposed observation window: seven elapsed days from start. Report UTC start-date cohorts and maturity timestamp explicitly; new cohorts still within seven days are incomplete, not failed or completed. Provisional charts must state partial observation.

Exclude only predeclared internal/staff accounts, synthetic load/tests/bots, duplicate starts belonging to the same instance, and accounts with an existing approved Brain before this initial-onboarding start. Document counts/reasons before comparing cohorts; no retrospective exclusion for slowness, failed import/provider, language, manual-only setup or abandonment. Opt-out/unavailable telemetry and corrupt/missing event joins are recorded as unmeasurable/instrumentation exclusions with counts, not assumed conversions. Content deletion/retention must not be bypassed to preserve metrics; retain only authorized minimized events/aggregates under the approved telemetry policy.

OnboardingInterrupted records exit or proposed 30-minute inactivity (an inactivity label, not removal from the cohort). Returning before the window ends keeps the same clock and instance. At seven days, no QualifiedFirstValue means not activated in-window; explicitly abandoned instances and otherwise inactive instances remain in the activation denominator. They have no finite in-window TTFV and are reported as censored/non-converting, never assigned zero or removed without disclosure. A later qualified output is late activation, reported separately; it does not rewrite the seven-day conversion result. Genuine exits/deletion terminate content access but do not create a successful metric.

TTFV median/p90 are calculated on distinct eligible instances with qualified first value within seven days (the converter distribution), using nearest rank: sort elapsed durations, take rank ceil(q × N), q=0.5 or 0.9. Always publish converter N, all eligible started N, non-converters/abandoned count, unmeasurable exclusions, observation window and instrument version alongside percentiles. With N=0, values are unavailable, not zero. Flag small samples; do not present fast converters as proof of good onboarding for the whole cohort. Also report the fraction of all eligible starts reaching first value within 10 and 15 minutes; non-converters count as not reaching the threshold. Whole-cohort/censor-aware analyses must be separately labeled rather than substituted for converter percentiles.

## Completeness — calculation version 2

Completeness is a transparent integer **0–100**, computed only from current valid approved facts and persisted with each BrandBrainRevision (score, missingMandatoryFields, ontologyVersion, calculationVersion, calculatedAt). Draft/unreviewed candidates, synthetic placeholders, invalid/blank values and future entities earn no points. With no approved head, display 0 with a clearly marked “not yet approved” snapshot state; do not fabricate persisted calculation or approval metadata.

| Slot / field                 | Weight | Satisfying condition                                          |
| ---------------------------- | -----: | ------------------------------------------------------------- |
| Organization.name            |      5 | Approved nonempty name                                        |
| Organization.industry        |      5 | Approved valid enum                                           |
| Organization.companySize     |      5 | Approved valid enum                                           |
| Organization.primaryRegion   |      5 | Approved valid region                                         |
| Organization.primaryLanguage |      5 | Approved valid language                                       |
| Brand.name                   |      5 | Approved nonempty name                                        |
| Brand.missionStatement       |     10 | Approved valid nonempty mission, within length limit          |
| BrandVoice.toneAttributes    |     10 | Approved MANUAL list of 2–4 allowed tone attributes           |
| Offer.name                   |      5 | Approved valid name on representative Product or Service      |
| Offer.description            |      5 | Approved valid nonempty description on that same member       |
| Offer.valueProposition       |      5 | Approved valid nonempty value proposition on that same member |
| Audience.segmentName         |      5 | Approved valid name on representative Audience                |
| Audience.description         |      5 | Approved valid nonempty description on that same member       |
| Audience.painPoints          |      5 | Approved nonempty valid list on that same member              |
| Recommended Competitor       |     10 | At least one active approved Competitor with nonempty name    |
| Recommended Primary Goal     |     10 | Approved valid primaryGoal enum                               |

Mandatory weights total 80; recommendation weights total 20. Higher mission/tone weights reflect their influence on brand-specific output. Score is the sum of satisfied weights, with no fractional rounding, time bonus, confidence bonus or score-based approval. Show earned/available points and missing mandatory paths; recommendation points cannot compensate for missing mandatory facts. Optional vision, vocabulary, sample writing, features and other fields do not add score under v2; still retain their provenance and validation.

For offers choose one active approved Product **or Service** with the highest satisfied required-field weight (tie by entity UUID); use its three fields together, never combine a name from one offer with a description from another. Choose Audience the same way. Missing groups report all three slot paths. Generation consumes complete approved members only; extra incomplete optional members do not block an already complete group or increase the score denominator. Record the selected member IDs in the approved artifact calculation metadata for reproducibility.

Version 2 supersedes the previous equal-weight/floor v1 calculation for new approved snapshots. Preserve historical v1 scores/calculatedAt unchanged; the example 13/14 mandatory slots plus both recommendations yielding 94 is v1 only. Under v2, missing a five-point mandatory field yields 95 with both recommendations, and missing a ten-point mandatory field yields 90. Switching the current scoring/ontology contract requires a new explicitly approved reevaluation revision, not an on-read rewrite. No duplicated score on Brand or independent writable analytics score is introduced.

## Readiness and useful limited functionality

Business readiness is a Boolean with reasons, independent of completeness. It requires a current approved revision compatible with the current ontology/calculation contract, all mandatory fields valid and approved, at least one complete approved Product or Service and one complete approved Audience, valid manual tone, and an unarchived Brand. Store approval-time readiness in the revision; calculate effective readiness by overlaying current archival/compatibility state without rewriting the historical snapshot. Relevant approvals include same-tenant valid source/derivation references and completed Owner confirmation; governance eligibility alone is insufficient. Pending replacement proposals do not replace the current approved field.

**Score ≥70 never bypasses a missing mandatory field.** Score 70 with missing mission or tone is not ready; score 95 with a missing five-point field is not ready. Score 80 with all mandatory fields and no recommendations is ready when the other readiness conditions pass. Even score 100 cannot override archival, absent approvals or incompatible ontology. Stale/unknown verification and pending contradiction flags are explicit warnings under KNOWLEDGE_PROVENANCE.md; they do not silently change facts or substitute for required approval. Authorization, resource limits, provider availability and Conversation deletion remain separate runtime request gates, not readiness or completeness points.

| User state                                      | Useful available functionality                                                                                                                          | Explicit limitation                                                                                                                                    |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 0 / no approved facts                           | Manual setup, one-source import, candidate review, static guidance and visible missing-field list                                                       | No business-grounded AI generation and no qualifying first-value output; templates/examples do not count.                                              |
| Approved but incomplete Brain                   | Edit/verify approved facts, review imports/conflicts, inspect/restore approved history, copy a partial approved Brief, read accessible existing history | Label Brief “Partial — based only on approved information”; list missing sections and readiness reasons. No new business-aware generation until ready. |
| Ready at 80–100                                 | Context-aware Workspace and usable approved Brief, subject to request gates                                                                             | Recommendation completion optional; no 100-point requirement or unreviewed context.                                                                    |
| Formerly ready, then mandatory removal/archival | Retain permitted history/knowledge inspection and correction; show current reason                                                                       | Disable new generation; previous activation is historical, not proof of current readiness. Deleted Conversations remain inaccessible.                  |

Do not answer from empty/low business context and quietly call it brand-grounded. If Context Engine fails to obtain approved context, the Workspace shows a recoverable context limitation and preserves the draft prompt. It can direct the Owner to approved information/setup; it does not bypass readiness with generic chat. Partial approved Brief copying is independent of Workspace generation readiness and must not invent missing facts.

## Exact event contract

All events have eventId (dedupe), eventName, contractVersion, occurredAt/serverRecordedAt, pseudonymous account/Organization IDs and Brand ID (nullable until Brand creation, required for qualified output), onboardingInstanceId where relevant, optional browser sessionId, cohort/source classification and instrumentation consent state. Server outbox emits committed revision/readiness/output events after successful transactions; a rolled-back approval cannot emit success. User actions are accepted only after tenant/ownership and related-record validation. Do not include source text, prompts, responses, fact values or personal business content in telemetry. Fact keys/revision references and opaque output IDs are sufficient; retention/access and consent periods require separate operational approval.

| Event (exact name)           | Producer / timing                                                                                | Required additional data and purpose                                                                                                                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| OnboardingStarted            | Server, first eligible initial setup entry                                                       | Stable startedAt and onboarding instance; eligibility class; start of clock and denominator.                                                                                                                 |
| OnboardingInterrupted        | UI exit or inactivity monitor                                                                    | Reason and last activity time; diagnostics only, no reset/exclusion.                                                                                                                                         |
| OnboardingResumed            | Server, reentry of same instance                                                                 | Original startedAt; joins sessions/devices.                                                                                                                                                                  |
| BrandBrainRevisionApproved   | Knowledge Management, after approval commit                                                      | revisionId, previousRevisionId, ontologyVersion, calculationVersion, completenessScore, missing mandatory keys, calculatedAt; persisted approved snapshot.                                                   |
| BrandBrainReadinessEvaluated | Server, approval or effective archival/compatibility change                                      | revisionId, effectiveReady, readinessReasons, evaluatedAt; retain old/new Boolean or derive transition under dedupe.                                                                                         |
| ImportSubmitted              | Import application, accepted source submission                                                   | correlationId, source type, submittedAt; funnel diagnostic, never approval/value.                                                                                                                            |
| ImportCompleted              | Import application, extraction eligible for review                                               | correlationId, completedAt, safe status; review readiness, never knowledge approval/value.                                                                                                                   |
| ImportFailed                 | Import application, terminal failure                                                             | correlationId, failedAt, safe error code; keep user in cohort, never erase waiting time.                                                                                                                     |

| OutputPresented              | Validated UI acknowledgement of final readable output                                            | outputId, kind=workspace_response or brand_brief, approvedRevisionId, grounding fact keys, validationResult, approvedContextPresent, isPartial; streaming token/render without final success cannot qualify. |
| OutputUsabilityConfirmed     | Supplementary: server accepts helpful/usable action or successful clipboard-copy acknowledgement | outputId, action=helpful or usable or copied, actionId, success flag; reject events for unpresented/invalid/wrong-tenant output. Helpful feedback maps existing basic response feedback to this signal.      |
| QualifiedFirstValue          | Server-derived once per onboarding instance                                                      | outputId/kind, approvedRevisionId, grounding checks, validated OutputPresented eventId, startedAt, qualifiedAt, elapsedMs; stop clock and count activation exactly once.                                     |
| OnboardingWindowClosed       | Cohort processor at startedAt+7 days                                                             | qualified/not_activated/unmeasurable outcome; censor time, interruption status, completion/readiness history; finalize seven-day denominator.                                                                |

Canonical historical terms map here: GenerationCompleted/Response Generated mean output production, not first value; Copy Response/Brand Brief Copied and helpful FeedbackSubmitted supply supplementary usage/quality signals after related-output validation; entering Step 5 or seeing “Wow Moment” is not activation. An explicit UI “usable” action is optional; no additional MVP screen or user approval of generated text is required by this measurement contract.

Outputs must have stable tenant-scoped identity and pinned approved revision/grounding references. For Brief presentations/copies derive an opaque identity from Brand+revision+partial/full view version; no ExportJob is needed. Presentation and supplementary usability requests validate the original response/Brief record and operation, not blindly trust browser-provided grounded=true. Offline/out-of-order delivery is deduplicated and may wait for prerequisite events, but qualification uses validated output-presentation receipt time; real missing joins remain unmeasurable. A later knowledge revision never relabels an old output as grounded in that newer revision. Generation pinned to an older snapshot that was valid when produced may qualify unless revoked/deleted or known invalid at presentation validation; do not treat a generic output as approved through later imports.

## Metric formulas and proposed goals

| Metric                              | Calculation / denominator                                                                                                  | Proposed goal, not observed                                                            |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| TTFV median                         | Nearest-rank median of qualified seven-day converters; all cohort/exclusion counts alongside                               | ≤10 minutes                                                                            |
| TTFV p90                            | Nearest-rank p90 of the same converter set                                                                                 | ≤15 minutes                                                                            |
| Seven-day activation rate           | Distinct eligible onboarding starts with QualifiedFirstValue by start+7 days / all eligible starts in a mature cohort      | >60% historical proposal, unvalidated                                                  |
| Seven-day readiness completion rate | Distinct eligible starts reaching effectiveReady=true at least once by start+7 days / all eligible starts in mature cohort | >70% historical proposal, unvalidated; this is a cohort rate, never a field-score gate |
| Current completeness                | Selected approved revision’s persisted weighted score                                                                      | 0–100 scale; no “≥70 means ready” goal                                                 |
| Current readiness                   | Effective Boolean + reasons for current approved facts/status                                                              | Mandatory-field/approval rule; no numeric bypass                                       |

Report readiness completion, activation, and completeness separately. A presented usable partial Brief can activate someone before they become generation-ready; completing the form does not activate someone without usable output. Other historical retention/paid-conversion/weekly-activity thresholds remain goals outside this onboarding contract, never reported here as measured results.
