# Public transport, authentication and mutation rules

Proposed contract1.0.0, gated by D-API-03 and [ADR-009](../../domain/08_BACKEND_AUTH_AND_CONSTRAINTS_ADR.md). [OpenAPI](1.0.0/openapi.json) and [matrix](ENDPOINT_MATRIX.md) enumerate exact operations and DTOs. All six domain services remain DI-only. Application controllers own public validation/projection; domain rules stay in their modules.

## Serialization and responses

UTF-8 JSON application/json, case-sensitive camelCase, UUID strings, UTC RFC3339 timestamps, integer completeness0–100; positive BIGINT sequence is a canonical decimal string up to9223372036854775807, checked semantically as well as by shape. Reject invalid UTF8/JSON, duplicate JSON object keys, unknown body/query fields and unsupported enums. Absent optional PATCH fields mean unchanged; explicit null clears only schema-nullable fields. Required null is deliberate unknown/no-reference, never omitted or silently converted to zero/empty. No generic arbitrary map of Prisma columns is writable. Reject empty PATCH (expectedRevisionId alone is not a change). Array edits replace that reviewed field atomically, not merge unknown members. User-provided approval/actor/sequence/tenant/model/status fields reject.

Non-stream success is `{success:true,data:<route DTO>,meta:{requestId,contractVersion:"1.0.0"}}`; failures retain the baseline `{success:false,error:{code,message,...}}` and add required safe requestId/retryable/retryAfterSeconds/fields. This is a **proposed compatible reader-first envelope amendment**, not evidence of released clients accepting it. Older readers that reject extra properties need an adapter or coordinated cutover (D-API-07). 204 and SSE have no JSON success wrapper. All responses carry authoritative X-Request-ID and protected responses Cache-Control:no-store; redact request IDs from public sharing if linked to support records. Input X-Request-ID is untrusted, validated, never an authorization/correlation identity. Artifact correlationId is separately returned only for accepted import/generation tracing.

Error codes and statuses are [machine-readable](1.0.0/error-registry.json). Precedence: enforce ingress byte/media limits safely without looking up a resource; authenticate; validate Origin/CSRF if applicable; resolve actual scoped resource including all nested parents/tombstones; parse typed content/references; authorize referenced revision/source; check replay; check new mutation preconditions; commit. For a known authenticated caller, foreign/missing/wrong-Brand/deleted IDs return identical404 RESOURCE_NOT_FOUND, including cursor/reference validation. Missing/invalid/revoked/expired session returns401 AUTHENTICATION_REQUIRED before object disclosure. 403 applies to rejected request Origin/CSRF or an authenticated capability forbidden independently of object existence; it is not a foreign-resource probe result. Enum Admin/Editor/Viewer grants no MVP permission.

400 MALFORMED_REQUEST covers syntactic errors; INVALID_CURSOR covers malformed/tampered same-scope cursor. 422 VALIDATION_FAILED covers semantic/DTO fields, required/unknown fields;413 byte cap,415 request MIME,409 business or concurrency. Missing required If-Match on an operation that uses it is422; mismatched If-Match is409 PRECONDITION_FAILED (no competing412 convention).429/503 may include integer Retry-After seconds matching nonnull retryAfterSeconds; all other errors use null unless reviewed retry policy says otherwise. Retryability never authorizes an automatic mutation replay with a new key. 500 is generic and internal traces/prompts/provider messages/tenant names never escape. Field errors use JSON pointer paths and safe fixed messages, no echoed passwords/source URLs/values. Public errors do not reuse internal Artifact error enums.

## Authentication — specified, no provider implementation claimed

Access JWT in Authorization:Bearer, browser memory only; never query/localStorage/cookie business auth. Validate issuer/audience/signature/algorithm/purpose/expiry and current AuthSession ownership/unrevoked/fixed expiry every protected request. Signup returns201, login/refresh200, logout204. Signup atomically provisions sole User+Owner+Organization but does not approve business fields or create Brand; profile values remain draft until explicit Brand publication. Baseline duplicate signup is proposed409 ALREADY_EXISTS with a generic body/timing/rate policy. **Residual blocking conflict:** immediate session issuance on successful new signup versus duplicate409 still exposes email existence through outcome, even without naming it. ADR-009 requires non-enumeration; D-API-03/Security/Product must review a uniform asynchronous acceptance/login handoff or another compliant signup UX before enabling this branch. No email provider/verification endpoint or changed approved auth flow is invented here. Generic messages/rate limiting alone do not resolve the oracle. Login failures use same401 regardless of unknown email/wrong password/revoked credentials. Exact identity normalization, email length/IDNA policy, password min/max/hash cost, credential request-byte limits/rates and abuse controls require Security approval; schema validates shape only and unconfigured policies fail503 POLICY_UNAVAILABLE. Never trim/normalize password bytes silently. Email normalization must be the same at signup/login and uniqueness lookup; no guessed provider-specific dot/plus rewriting.

Refresh is signed separate-purpose JWT in `__Host-refresh`: Secure;HttpOnly;Path=/;SameSite=Lax; no Domain. Refresh/logout read this cookie only after allowlisted Origin plus CSRF checks. Signup/login also check Origin to prevent login CSRF. Recommended CSRF contract: non-simple X-CSRF-Protection:1 header **and** exact allowlisted Origin, reject absent/null/mismatch; deployment must support browser Origin and preflight, no wildcard/reflective credentialed CORS. This selected contract needs Security review (D-API-03); no double-submit secret/bootstrap endpoint is invented. Host-only cookie and browser fetch credentials:include; use TLS, exact frontend origin, Vary:Origin, explicit allowed methods/headers (Authorization, Content-Type, Idempotency-Key, X-Accepted-Request-Key, X-CSRF-Protection, If-Match), expose X-Request-ID/ETag/Retry-After; prohibit unreviewed cross-site deployment that breaks Lax.

Rotation atomically replaces refresh hash/jti without extending fixed family expiry; validated old signed token reuse revokes family. Browser serializes refresh across tabs using a reviewed same-origin coordination mechanism, never shares access tokens in persistent storage. Lost refresh acknowledgement cannot safely replay the old token under ADR-009; clear local credentials and require login, do not invent grace/replay. Logout requires valid cookie+CSRF, revokes current family, expires cookie using same attributes; invalid/revoked cookie401 and clear it, never disclose session identity. No bearer-only logout alternate. Logout failure UI clears memory but cannot claim server revocation; display reauthentication/network recovery. Proposed15minute/seven-day lifetimes remain pending. Refresh/revocation/keys/clock skew/provider terms remain separate review gates.

Server checks live sole Owner membership and actual Organization→Brand→entity lineage, source/revision ownership, archival/readiness, Conversation.deletedAt and authorization again after await before writes/stream/publication. Feedback target must be an authorized validated COMPLETED ASSISTANT. No account/tenant IDs from body/token alone grant access. On401 UI clears tenant data and asks login; on404 purge scoped UI cache, do not probe alternate tenants.

## Mutations and concurrency profiles

`Idempotency-Key` is a client-generated unguessable opaque value matching the OpenAPI syntax (recommended UUID); same logical submission retains key until resolved. Scope = current User+Organization+Brand+operation kind+canonical route/resource identity+key. Never use a global key namespace or return another caller's receipt. Hash canonical parsed typed payload plus route/method/scope, not raw multipart boundaries; file imports additionally hash exact bytes/MIME/safe filename metadata, URLs hash submitted validated text (URL alone is not source-byte identity). Actor/scope/time resolved by server. Reauthorize before replay and before conditional cache results. Key reuse different body gives409 IDEMPOTENCY_CONFLICT; stale **new** knowledge mutation409 REVISION_CONFLICT; identical committed replay precedes current-head comparison and returns original business result (fresh requestId meta allowed).

Organization PATCH before Brand creation locks Organization, expectedRevisionId=null, records draft changes and returns INITIALIZED with newRevisionId=null and score0/no persisted time; it cannot approve facts without a Brand. Brand initialization may create draft skeleton (no Document/job) or publish explicitly submitted valid manual fields through KM; publication returns PUBLISHED + actual revision. Draft field defaults are not approved facts. Edits after head exists always publish explicit reviewed changes through KM, including Organization/voice/entity deletions. Draft repeatable members may be incomplete in UI but only a valid complete typed member can publish through entity POST; UI keeps unsaved incomplete rows locally, labels them draft. Missing mandatory fields do not block other valid approved fields/limited Brief; readiness alone blocks generation.

No global durable receipt is assumed. Existing Artifact JSON key lookup uniqueness is enforced by reviewed Brand/Conversation lock/transaction gateway, not a new enum. Exact receipt storage windows/rates/body/file limits, retention and expiry behavior require D-API-03/D-POL-01/D-GW-01. Keys may not be reused to recreate operations after receipt expiry; return409 when trustworthy identity is unavailable, require explicit new logical request and review. Retention cleanup cannot erase approved version history or resurrect deleted Conversation data. In-progress claim loss uses internal fenced reconciliation, not client retry allocating a second operation.

ETags: conditional GET supported on import status only (quoted existing projection.version); If-None-Match yields304 empty after full current authorization and version evaluation. Other GETs use no-store without304 until reviewed representation validators. expectedRevisionId is the single authoritative approved-head precondition; no invented competing resourceVersion. Optional If-Match on knowledge mutations, if supplied, is quoted expectedRevisionId and must agree with body; mismatch409. Organization pre-Brand writes use transaction serialization but no fictitious revision/ETag. Last-write-wins draft profile contention and signup completion remain review risks, not approved silent merges.


## DTO reference and field invariants

All optional properties are listed explicitly in JSON Schema required arrays; no implicit defaults on publication DTOs. Empty optional text can remain a draft value where allowed, never a complete mandatory approved fact. `expectedRevisionId:null` asserts no approved head, not “ignore version”. `currentRevisionId:null` pairs NO_APPROVED_HEAD completeness0 with null ontology/calculation/time and readiness=false. PERSISTED completeness copies its actual immutable revision; source/quality availability never recalculates historical score. Revision metadata reads require PERSISTED completeness; initialization Publication may use NO_APPROVED_HEAD. RevisionDetail facts are the authorized full **scalar field view**, not raw Artifact JSON; unsupported relationship-aware exact restore remains blocked under D-REL-02.

Fact.valueRevisionId identifies introducing approved value; supersedesValueRevisionId is prior value revision or null. approvedByUserId/approvedAt resolve that introducing approval (not a guessed latest editor); lastVerifiedAt is actual explicit verification or null, including preserved dates on restoration. Imported/derived source expansion follows exact historical binding; SourceDisplay.documentId must be same authorized tenant and can be a retained safe identity after bytes deletion. Manual facts have sources=[] and need no Document. Imported source URLs/labels/excerpts are inert bounded display data, never HTML, automatic remote fetch or source instruction. Source precision maps verified original literal spans→EXACT, verified original structural anchors→STRUCTURAL, only normalized text→NORMALIZED_ONLY, absent original location→UNAVAILABLE, failed validation→INVALID. Availability is current access to retained source bytes, distinct from past precision. Unauthorized source must not disclose its identity/label/excerpt: omit protected source expansion and use safe SOURCE_UNAVAILABLE warning, or404 if required by operation. Source deletion blocks new imported approval; existing history shows truthful unavailability.

Candidate.id is a server-assigned stable public UUID resolving **one actual frozen original Artifact/item pair** in the authorized correlation; persist/reconstruct its canonical mapping under reviewed D-API-03 adapter, never choose an ambiguous item match or treat Artifact ID as item ID. `value` on edit is a typed FieldValue; entityType/entityId/fieldPath must exactly equal the target frozen candidate. Only the value may change, under existing field manual/import eligibility and evidence revalidation; attempt to redirect the edit422. Any original nullable extraction confidence maps public Quality.UNKNOWN/null unless a reviewed assessment supports a known value; no invented formula. Pending candidates are not Fact.approvalStatus APPROVED. Contradictions reference authorized current approved facts and are review warnings, not automatic replacements.

DecisionResult newRevisionId is nonnull on confirm/edit publication and null on delete/reject; status is original full lifecycle projection. Candidate counts come from all frozen items/decisions, not the current page. Known confidence integer bounds and unavailable/null cross-field invariants are structural; formula/version/subject ownership is server-validated. BrandStatus/ArtifactStatus are not exposed as user-settable fields. Public aliases are mapped in compatibility notes. Brand archive, relationship edits, arbitrary scoring fields and locale migration flags are not writable through generic PATCH.

Message.operationId/correlationId/approvedRevisionId are nonnull for new accepted ASSISTANT attempts; replyToUserMessageId same Conversation USER; content only nonnull for durable COMPLETED, feedback only actual vote on completed ASSISTANT. failureCode required semantic mapping FAILED/GENERATION_FAILED, TIMEOUT/GENERATION_TIMEOUT, CANCELLED/GENERATION_CANCELLED; pending/completed null. retryAvailable true only reviewed latest eligible terminal attempt; never USER/pending/completed/deleted. RecoveredAttempt requires same selectors/Conversation; failed result cannot be shown final. Nonempty content and real validated RESPONSE linkage remain transactional requirements beyond structural JSON.

Message.contextLimitation is null until selection known, then NONE/HISTORY_LIMITED/CURRENT_REQUEST_ONLY from actual approved history policy. Completed ASSISTANT reads/stream finals require a known disposition; current-only remains approved-knowledge-grounded and gated D-HIST-02. This small limitation notice is not Context Inspector/source-review expansion.

Repeatable-entity and candidate list pages include currentRevisionId for the exact displayed knowledge snapshot/head; use it as expectedRevisionId when reviewing edits, never replace it with a newer head without re-review. Candidate page current head and frozen candidate identity are separate. Typed diffs before/after include Fact provenance/approval/source expansion, not only scalar values; at least one side is nonnull, ADDED has null before, REMOVED null after. Membership/relationship restoration consequences remain gated rather than dropped.
