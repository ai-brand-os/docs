## Accessibility contract A — every row

Native labelled inputs/buttons, keyboard submission without duplicate dispatch, visible focus indicator pending approved tokens, focus stays on initiating control during background updates; no focus-stealing on each token/poll. Error summary receives focus after rejected explicit save and links to aria-describedby/aria-invalid fields; retain user input except secrets. Saving/loading uses aria-busy with concise polite status; terminal failure uses role=alert once, no token-by-token screen-reader flood. Stream announces response start and final/failed state, not every chunk. Color never sole status cue, motion reduced per preference. Deletion confirmation names the action/scope, keyboard trap only in actual modal, cancel preserves focus, completion returns focus to list/new conversation control. Disabled buttons expose reason; stalled request has safe explanation/recovery without enabling duplicate generation. Meet reviewed contrast/target-size/responsive requirements before release; this file supplies behavior, not invented Design Foundations values or certification.

Account profile: input→submitting→authenticated or inline401/422/409 safe error;401 on protected data clears memory and redirects to existing login flow. Refresh lock waits, loses acknowledgement→require login; no endless refresh loop. Logout pending→memory cleared→revoked only after204; network error cannot claim revocation. Single Organization is static text, never keyboard dropdown. Auth forms never echo passwords or preserve them in analytics/logs.

Readiness changes do not delete Conversation history. Review conflict never discards an already committed approved candidate. Input retains safe local edits on503, but app/logout/deletion clears tenant content. Component/visual dependencies and screen placement remain [pending](DESIGN_DEPENDENCIES.md).
