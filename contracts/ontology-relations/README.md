## Contract rules

All fields in each schema's `required` list are required; closed objects reject unknown properties. `null` is allowed only for explicit nullable backward-approval links and derived-rule references; absent fields never mean null, unknown relationship history never means an empty graph. Maximum cardinality `null` in the registry means no domain upper bound, subject to snapshot/resource limits. `persisted` means separately serialized explicit edges; false does not mean ownership FKs or source facts are unpersisted. Empty origins on structural/derived views means inherit actual record/fact provenance, not permission to invent an edge origin. All relationship directions are source→target; reversed traversal is a read view of the same identity, not a second edge. IDs use lowercase UUIDs and the ADR's exact typed-tuple SHA256 rule. Knowledge fact keys are virtual identities, not entity UUIDs.

The containing Artifact supplies organizationId, Brand, correlationId and immutable artifact identity; graph supplies ontology/registry/revision. Duplicate scope/revision fields must agree. Approver/time are resolved through the referenced authorized decision and BrandBrainRevision; model output cannot supply authority. Supporting facts point to actual approved snapshot/fact/value revisions; evidence refs point to an authorized original-candidate Source Evidence binding, not free-text coordinates. Manual edges need neither Document nor fake evidence. Imported predicates require real supporting literal facts and separate human predicate approval. Stale support excludes current automatic use pending review.

Validate schemas first, then ADR-014's cross-record rules: exact versions; registry pair and direction; authorized tenant/Brand; retained typed ownership and selected approved membership; identity uniqueness/cardinality; allowed origin; real approval/provenance; readiness and archival/deletion overlays. Reject Reserved and unknown types. Error categories in the reference model (`SAFE_404`, `PAIR`, `OWNERSHIP`, `TENANT`, `BRAND`, `DANGLING`, `IDENTITY`, `DUPLICATE`, `VERSION_GATE`, `MIXED_REVISION`, `APPROVAL`, `SUPPORT`, `EVIDENCE`, `NOT_READY`, `POLICY_DISABLED`, `STALE_REVISION`, `IDEMPOTENCY_CONFLICT`) are internal conditions mapped to existing API safe 404/403, 409 conflict/compatibility or 422 validation contracts; they are not new Artifact error enum values. Never expose foreign identities in errors.

## Authority and lifecycle

Existing FKs and approved membership represent ownership. Only explicit TARGETS/COMPETES_WITH assertions belong in snapshot edges. PRODUCES/ORIGINATES_FROM share approved evidence; MAY_DESCRIBE is exact fact-key lookup. USES is read-only derivation and disabled pending D-REL-02. Explicit relationship writers are also disabled until reviewed transport/product semantics exist. Global approved BrandVoice injection does not imply Product USES Voice. Reserved relationships cannot be instantiated.

ACTIVE/ARCHIVED approved members remain reconstructable; REMOVED dispositions are retained identity tombstones outside current members/facts. Current retrieval filters archived/removed/deleted endpoints without rewriting historical edges. Archive/reactivation writes require D-REL-03; current member removal already exists. Rename preserves UUID/edge ID; recreate gets new UUID. Source-byte erasure does not cascade approved facts; lawful tenant erasure may destroy reconstructability under existing pending retention policy.

No join table or graph DB: snapshot edge lookup is sufficient for bounded MVP reads. Existing business/KnowledgeIndex tables are projections. Optional future caches require snapshot/revision/digest scope, canonical fallback and idempotent rebuilding; no cache is authority. One-hop retrieval caps 32 edges/32 endpoint nodes and emits truncation reason. Bounds/rule activation await review.

## Versions, migration and rollback

[Proposed Artifact2.3](../artifacts/2.3.0/README.md) adds recorded graph, relationship-only approval and selected context refs because earlier closed schemas cannot express them. Preserve every earlier version byte-for-byte. Inventory historical snapshot versions, deploy strict reader dispatch before gated writers, validate existing authority/reference lookups, and test restore/rollback in a real transaction environment. No fabricated edges/backfilled approval dates. Old snapshots expose `NOT_RECORDED`; legacy restoration with a current recorded graph blocks until an authorized migration/reset/preservation preview policy is reviewed. Exact 1.2 graphs can restore exact tuples into a new revision, reapproving reinstated edges, never regenerating relationships.

Rollback disables new writers; retains 2.3 readers or blocks affected Brands safely. Never strip graph fields and feed a downgraded snapshot to an old reader, or rewind the head pointer. Unknown/corrupt versions are quarantined and fail safely. No Prisma/DDL migration proposed. D-REL-01 owns version rollout; D-REL-02 owns semantic/default/review transport and derivation; D-REL-03 owns lifecycle controls. [Tests/results](../../validation/TASK20_RESULTS.md) distinguish offline specification checks from runtime proof.
