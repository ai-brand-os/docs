# Source evidence contracts 1.0.0

Date: 2026-10-18. **Specified — Pending Architecture/Product/Security Review (D-AUD-05)**. [ADR-013](../../domain/12_SOURCE_EVIDENCE_MAPPING_ADR.md) owns representations, mapping algorithms, format/security/retention rules and responsibilities. Schemas and fixtures are a reviewable design, not an implemented parser, storage service or proof of fact truth.

## Canonical package

[Registry](1.0.0/registry.json) pins Draft2020-12 schemas: [manifest](1.0.0/manifest.schema.json), [binding](1.0.0/binding.schema.json), [typed location](1.0.0/location.schema.json). URNs resolve locally only. Validate bytes/format bounds before JSON parsing, reject unknown versions/properties, duplicate object keys, nonfinite/unsafe numbers and invalid Unicode; no coercion, defaults, stripping or network schema loading. All schema properties are required; nullable values are explicit, never fake coordinates/empty IDs/zero confidence. Array order is meaningful for maps and evidence spans. Review policy/configuration must set finite limits no larger than defensive schema ceilings; ceilings are not approved launch budgets.

| Location discriminator | Exact required shape / semantics |
| --- | --- |
| TEXT_SPAN | span {representationId,contentSha256,start,end,unit,quote}; retained text representation, nonempty half-open range. quote=null means no quotation claim; a non-null quote must equal the selected text exactly |
| PDF_PAGE_SPAN | source {representationId,contentSha256} identifies PDF bytes; pageNumber≥1 physical page; textSpan identifies pinned parser text; anchorId, parser {id,version,configSha256}, bbox nullable. A source-byte range is not a PDF text span |
| HTML_ELEMENT_OR_TEXT_SPAN | Immutable HTML source ref, parsed textSpan, captured anchorId, elementId nullable, parser ref, displayUrl nullable. URL/selector alone cannot identify evidence; displayUrl must match retained capture metadata |
| STRUCTURAL_SECTION | representation ref + anchorId; anchor must exist in the retained parser/capture catalog, not a guessed heading string; no fabricated precision |
| NORMALIZED_ONLY | span into NORMALIZED/CHUNK plus originalUnavailableReason; original page/text offsets explicitly unavailable |
| UNAVAILABLE | Known representation ref + typed reason; no page/offset/quote fields accepted. Missing identity is invalid, not an anonymous unavailable citation |

Typed unavailable reasons: SOURCE_DELETED, SOURCE_AVAILABILITY_UNKNOWN, MAPPING_LOST, AMBIGUOUS_ORDER, NO_TEXT_LAYER, PARSER_UNSUPPORTED, LEGACY_UNMAPPED, ORIGINAL_NOT_RETAINED, UNSUPPORTED_ENCODING. They never authorize bypassing source identity/tenant checks. Live retained/deleted/unknown state comes from the storage/lifecycle gateway separately from historical locator/receipt.

Offset units: UNICODE_CODE_POINT means Unicode scalar positions in **logical stored order**, not UTF16 indexes, grapheme clusters or screen glyphs. UTF8_BYTE means offsets into the exact UTF8 bytes, with boundaries validated by strict decoding. All ranges are [start,end), start<end. No binary-PDF text slicing. Text digests hash exact UTF8, no implicit normalization/newlines/BOM changes; source binary digests hash exact stored bytes. Multibyte Persian/Arabic/emoji/combining characters require explicit conversion. Exact quotation of NFC text must not be presented as quotation of different original combining bytes. Bbox coordinateSystem is PDF_POINTS_CROP_TOP_LEFT with actual parser-verified crop/rotation/page dimensions; null if unavailable.

## Representation and map manifest

Manifest includes existing sourceId/sourceArtifactId/sourceDocumentId/rawIntakeArtifactId and tenant/Brand/correlation. Here sourceArtifactId is the actual final STRUCTURED_DOCUMENT; rawIntakeArtifactId separately identifies original intake. Capture identifies the immutable upload or bounded HTTP body with format/time/version/config, requested/final URLs/redirects, MIME/charset, body convention and PDF page count where actually known. Redirect metadata is descriptive after SSRF-safe capture; it never grants permission to fetch during verification.

Representations have UUID/kind SOURCE/PARSED/NORMALIZED/CHUNK, digest/byteLength/encoding/coordinateSystem, parents, transform version/config, private content reference and retained anchors. One SOURCE root; no cycles or cross-source parent reuse. Its PRIVATE_OBJECT key, exact source digest/byteLength, sourceId and rawIntakeArtifactId must match the actual authorized RAW_INTAKE receipt, not a different object declared by the manifest. Other representations may use ARTIFACT_TEXT. Content reference is either PRIVATE_OBJECT with a server-owned immutable object key/version convention, or ARTIFACT_TEXT with exact immutable Artifact ID/JSON pointer. Do not accept arbitrary HTTP URLs as content references. Manifest owner and every content reference must match source tenant/Brand. A current Document.latestArtifactId is not a historical representation locator. source/normalized content may already exist in objects or v2 text fields; the manifest references it, not a second fact database.

Transforms specify output/input IDs, pinned implementation, classification REVERSIBLE/SPAN_TRACKABLE/PARTIAL/LOSSY, segment partition and omittedInputSpans. Each output segment has code-point start/end and relation EXACT/TRANSFORMED/GAP with ordered input spans. Input spans reference actual retained parent representations/digests. EXACT requires one equal-length/equal-text input range before affine clipping; TRANSFORMED covers whole normalization/entity/whitespace units without proportional interpolation; GAP has no parent range. Omitted input is explicit. Compose to multiple source spans; never replace them with a bounding range over deleted/reordered text. Missing/lossy maps preserve last verified representation and reduce precision. [ADR transformation table](../../domain/12_SOURCE_EVIDENCE_MAPPING_ADR.md#transformation-map-strategy) defines each format/stage.

Anchor records bind page/text-unit/element/section IDs to representation, optional verified page/range/bbox, reading-order confidence class and visibility class. A model cannot create anchors. Parser-native order/units are converted with a tested adapter. Inert HTML cannot guarantee CSS/JS-rendered visibility; hidden/script/unknown-content handling is explicit. No OCR, rendering screenshots or monitoring is introduced.

## Candidate binding, validation and policy

Binding references original candidate Artifact/item, manifest Artifact, existing source/Document/tenant/correlation and evidence-policy version. entries bind stable evidenceId and exact legacyEvidenceHash to typed locators, literal-versus-interpreted support, and server validation receipt. legacyEvidenceHash is SHA256(stable-json-v1 of the **existing full four-field sourceEvidence DTO**), preserving sourceLocation's exact fields/units as historical input; a hash does not validate ambiguous legacy units by itself. Hashes must uniquely cover every sourceEvidence entry in that candidate. Reject duplicate/foreign/dangling evidence IDs and mismatched source refs. Binding parent Artifact is the actual original extraction candidate. No fact values, approving actor or second approval status are added here. New eligibility requires VALID selected attachments; ARCHIVED attachment reads are historical only, never permission for a new imported publication.

support.kind is LITERAL, INTERPRETED or UNRESOLVED; literalTexts are exact claimed excerpts, each matched to a verified locator quote. proposedInterpretation/basis nullable; ambiguityFlags cover currency/date/number/phone/URL/visibility/reading order. Values such as `$149` or `01/02/2026` remain literal and unresolved without actual supporting locale/currency evidence. Inferred meaning is not exact imported support; correction/manual confirmation follows existing provenance. No D-AUD-03 confidence formula is selected.

Validation receipt classification: VERIFIED_EXACT, VERIFIED_STRUCTURAL, NORMALIZED_ONLY, UNAVAILABLE, INVALID; timestamp/version/reason codes record the validation event. These are evidence classifications, not ArtifactStatus/knowledge approval. Schema structure cannot authenticate a receipt: KM computes/verifies it server-side against actual bytes/maps/anchors before persistence. UNAVAILABLE is not automatically INVALID. Imprecise original location can receive warning review with genuine safe source/normalized/structural support; fabricated quotes/digest/unit/reference errors are ineligible. No retained source permitting human inspection means new imported publication requires correction/reconstruction/manual review. Per-category policy and warning requirements remain **D-EVID-02** pending.

Known validation failures normalize to INVALID classification/ineligible; the offline helper throws safe validation codes before persistence rather than trusting or storing a forged receipt. reasonCodes uses the registered bounded code list, never parser/provider error bodies. Current availability is a read overlay, not an update to the immutable receipt. A historically VERIFIED_EXACT binding can currently have original bytes DELETED or UNKNOWN. Do not display its old classification as proof of current inspectability. Other retained representations support only their own exact content and labeled precision. No classification automatically approves a candidate or reopens an import.

## Artifact extension and historical binding

[Proposed Artifact2.2 registry](../artifacts/2.2.0/registry.json) and wrappers [representation_manifest](../artifacts/2.2.0/representation_manifest.schema.json), [evidence_binding](../artifacts/2.2.0/evidence_binding.schema.json) reuse the existing Artifact table/enums. Representation manifest is PROCESSING_INTERMEDIATE / DOCUMENT_PROCESSING / evidence_manifest; binding is KNOWLEDGE_CANDIDATE / KNOWLEDGE_MANAGEMENT / evidence_validation. Both successful immutable attachment records use exact schemaVersion2.2.0, own invocation/checkpoint identity, status VALID (historical ARCHIVED only under policy), operationStatus SUCCEEDED and error=null. Attachment recording success does not mean valid fact/eligible candidate/approved knowledge. Invalid evidence can have a validly recorded INVALID classification; do not confuse this with ArtifactStatus INVALID. Rejected malformed/unsafe attachments use existing safe errors, not fabricated successful records.

Processing atomically persists the final existing v2 STRUCTURED_DOCUMENT and its uniquely bound manifest. KM atomically records exactly one immutable evidence_binding for an original candidate key and verifies eligibility before final governance/policy_engine and ADR-012 REVIEW_OPENED. Enforce uniqueness under existing Brand/source/candidate reference locks and protected application writes; Prisma has no new JSON unique guarantee. Unique schema/version is not uniqueness of data. Retry checks scoped immutable receipt and exact hashes; different content under the same original candidate binding is conflict. New parser/map repair requires a **new** candidate/manifest identity under an authorized workflow, never in-place repair or multiple competing bindings.

Existing v2 evidence arrays, candidate decisions and approved snapshots are unchanged. Source bindings resolve using original candidate Artifact/item and exact evidence tuple hash. Approved imported fact provenance follows introducing valueRevisionId to its immutable revision/snapshot's candidate_decision parent, then original candidate and unique binding. Restores follow actual restoredFrom/fact history, unchanged facts retain original introducing IDs and list-item provenance remains scoped. If an ambiguous/missing lineage prevents resolution, report unavailable/quarantine new publication; do not choose newest binding, attach another tenant's identical digest or relabel a manual value as imported. A manual edit may retain old citations as historical inputs but does not gain original literal support for its changed meaning.

Attachments are **reference dependencies**, not additional inputs to the existing import aggregate state resolver. Load/validate them before returning selected complete governance; do not pass them as pipeline/control events or extend 2.1 stageBindings/public status. Unique binding existence is a governance prerequisite after adoption; frozen candidate refs implicitly pin it. Retried parser output, stale attachments and late repairs cannot replace frozen candidates or reopen CLOSED. Existing Artifact2.0/proposed2.1, Gateway1.0 and import projection1.0 remain byte-identical. No new model, independent evidence authority, approval ledger, provider path or public endpoint.

## Compatibility and rollout

1. D-EVID-01 Architecture/Engineering/source/KM owners review exact2.2 wrappers, uniqueness/history lookup, reference/deletion handling and consumer changes. D-EVID-02 Product/Architecture/Security reviews warning/correction policy; D-SEC-01 actual parser/capture versions/budgets and D-POL-01 retention stay open. D-AUD-07/D-IMP-LC-01/D-AUD-08 approvals are not inherited or closed.
2. Inventory real legacy sources/objects/units/quotes/parser versions and historical importing decisions. Keep old raw artifacts and v2 readers. Deploy local source-evidence1.0/Artifact2.2 readers **before** attachments/writers. Rehearse dangling/corrupt/deleted/cross-tenant and restore cases; no production migration is performed here.
3. Legacy records lacking known units/maps/bytes/lineage are LEGACY_UNMAPPED/UNAVAILABLE, not retrospectively verified. Do not infer page/offset from matching text, current website, current Document pointer or guessed parser. Lawfully retained bytes may be reprocessed under a new explicit parser/manifest/candidate identity after authorization; never mutate old fields or manufacture an old verification date. Existing approved values remain approved history with evidence warnings; no automatic reapproval or replacement.
4. Enable reviewed new source/manifest/binding writers and eligibility/publication checks atomically. No Prisma migration is needed for JSON storage. Actual reference lookup/transaction/index or queue-library migrations still require separate review and tests. Source/KM writes and cleanup share locks so lawful removal cannot race new dangling references.
5. Rollback disables new evidence-dependent writes/import approvals, retaining mixed readers, all original artifacts/manifests/bindings/approved revisions and deleted-content tombstones. Old readers must not consume 2.2 attachments. Do not roll back by removing evidence identity, resurrecting deleted bytes, reverting head or overwriting adopted versions. New fields/events/semantics require a new registered version.

Private object/text/excerpt reads recheck current membership/tenant/Brand/source and lifecycle, including conditional caches; no non-revocable source URL bypass. Objects/maps/quotes/identity metadata have separately approved retention and backup policies. Raw-byte deletion leaves only authorized retained identity and an unavailable overlay; it does not guarantee excerpts remain viewable. Logs redact text/full URLs/credentials; hash access is scoped. Reference scanning includes historical snapshots/decisions/bindings/manifest graphs and coordinates cleanup; orphan/corrupt refs block new publication and alert. Locator quotes and support.literalTexts are sensitive content copies: include them in independently approved erasure/redaction inventories rather than treating immutable JSON as an exception. A lawfully retained saved excerpt supports only an explicitly labeled excerpt, not continued original-byte inspectability. No new retention period or compliance assertion.
