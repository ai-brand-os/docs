# Proposed Artifact2.4.0 — quality assessment attachment

**Proposed — Pending Architecture/Engineering Review D-KQ-03.** [ADR-015](../../../domain/14_KNOWLEDGE_QUALITY_AND_TAXONOMY_ADR.md) and [quality1.0 contracts](../../knowledge-quality/README.md) define semantic validation. No prior version bundle is modified; no Prisma/SQL migration now.

[Schema](quality_assessment.schema.json), [registry](registry.json), [example](quality_assessment.example.json). Exactly PROCESSING_INTERMEDIATE / quality_assessment, stage quality_assessment, status VALID, operationStatus SUCCEEDED/error=null. Allowed producer DOCUMENT_PROCESSING owns categorical source-evidence metadata only (scores must be empty; no invented detector formula), KNOWLEDGE_EXTRACTION owns candidate extraction score, KNOWLEDGE_MANAGEMENT owns approved-entity support assessment, CONTEXT_ENGINE owns context coverage. These are not interchangeable producer permissions; actual subject/indicator producer pairs require reference validation. A successful assessment can report NOT_EVALUATED/UNKNOWN/INVALID without claiming pipeline or knowledge success. Failed creation writes no successful attachment; existing registered operation errors/checkpoints remain their old versions, no new error/status enum.

ParentArtifactId equals subject.subjectArtifactId. Envelope/assessment tenant/Brand agree; correlation and conversation ownership match actual subject. Subject is actual retained Document-processing metadata/candidate/approved snapshot/context, not a fabricated approval. Pre-head candidate/document metadata may have null revision; approved-entity/context require actual same-Brand revision/snapshot. Context refs bind the same revision used by selectedKnowledge/selectedRelationships. Assessment has operationId, exact semantic input/result hashes and original policy decision ref. No automatic approval, repeated import state event or new mutable score database.

Canonical subjectKey is original candidate UUID for CANDIDATE, `entityType/entityId` for APPROVED_ENTITY, subject context Artifact UUID for CONTEXT, and `document` for DOCUMENT_METADATA. Resolve it against actual original candidate/snapshot membership; arbitrary aliases cannot create parallel assessments. Approved-entity operationId equals the actual snapshot parent terminal commit operationId. The publication locks admit one final assessment per `(operationId,subjectArtifactId,subjectKey,indicator)`; formula/inputHash must match on replay, differing input is a conflict/new operation. Generic assessment dedupe also uses subjectArtifactId + subjectKey + indicator + formulaVersion + inputHash. All are application invariants under the shared reference lock, not existing DB uniqueness guarantees. Publication assessment resolves historical index meaning via that terminal operation; later reassessment does not rewrite its projected score without a new approved reevaluation revision. Validate schema then actual producer/subject/type/tenant/revision/approval/source/policy refs and recompute arithmetic/hash. Do not let a client create trusted PASS inputs. Immutable assessments add explanation/audit metadata about a snapshot, never independently edit its knowledge. Existing approval references remain sole governance authority. Imported evidence references remain Task19 bindings, not copied offsets.

Historical2.0–2.3 readers dispatch unchanged; new readers load2.4 explicitly. Pipeline dispatchers recognize this as a non-state attachment; it cannot select an attempt, release admission, satisfy review coverage or close an import. New attachments must not enter old lifecycle resolvers as fabricated processing checkpoints. Current contracts lack full disposition/formula/input fields; the extension is necessary for persistent auditable new scores, not a reason to rewrite them. Reader-first inventory/trusted lookup/uniqueness/transaction tests precede gated writers. Baseline old confidence fields stay null/null unless known assessment exists. Rollback disables writers/formulas and retains readers or fails safely; no stripping history/downgrading. Deletion follows owning subject/conversation/retained business policy and reference-aware purge; no new retention period.
