## Envelope, payload and null rules

Every envelope requires `artifactId`, `artifactType`, `parentArtifactId`, `conversationId`, `correlationId`, `organizationId`, `producingService`, `producingStage`, `schemaVersion`, `status`, `createdAt`, and `payload`. Wire `artifactId` maps exactly to Prisma `Artifact.id`; other names map to their camelCase Prisma fields. Do not add a second `id`, snake_case storage columns, approver, ontologyVersion, timestamp or model metadata to the envelope. Database/ORM objects must be explicitly serialized, not spread into wire responses.

Every payload requires `variant`, `operationStatus`, `brandId`, `invocationId`, `attemptNumber`, `checkpointNumber`, `data`, and `error`. Intake additionally requires `source` (sourceId/sourceType/originalFilenameOrUrl). Processing/extraction additionally requires `sourceDocumentId`. All required nullable properties **must be present**: omission is invalid; null means the expressly stated absence, not an empty string, unknown UUID, zero score or inferred value. Optional properties exist only where the schema omits them from required, primarily individual source-location anchors. Empty arrays mean a known empty collection. Unknown measurements use explicit nulls, not zero. `data=null` means no result exists at that checkpoint; it never means a business fact was cleared.

- PENDING: `data=null`, `error=null`. Captures accepted stage work awaiting a result; not an additional domain job table or generation state.
- PARTIAL: typed nonempty result/fragment, `error=null`. Captures an incomplete internal stage result. It cannot be forwarded as a final document, approved snapshot, final context/prompt or completed answer.
- SUCCEEDED: required complete result for that variant, `error=null`. Stage success does not approve knowledge, finish an import, finish a Conversation, or prove output presentation.
- FAILED, CANCELLED, TIMEOUT: required normalized `error`, typed diagnostic fragment or `data=null`. The fragment is not consumable success. Cancellation/timeout never create ArtifactStatus CANCELLED/TIMEOUT.

`sourceLocation=null` requires a nonempty `locationUnavailableReason`; an available location requires that reason=null. Character bounds require coordinateSpace ORIGINAL or NORMALIZED and a start/end pair. Original offsets may remain unavailable under D-AUD-05; a normalized location must identify its coordinate space and cannot be rendered as an original page offset. `verificationDueAt=null` means no reviewed deadline; `verifiedInRevisionId=null` means not explicitly verified. `expectedRevisionId=null` means initial approval against no head, not “ignore concurrency.” `supersedesValueRevisionId=null` means first value. `manual=null` is required for IMPORTED/DERIVED; `derivation=null` for MANUAL/IMPORTED. Imported facts require actual source Artifact and Document IDs, plus location or unavailable reason. A review rejection has `resultingRevisionId=null`; successful publication requires a real preallocated revision UUID.

## Lifecycle matrix and consumption

| payload.operationStatus | Allowed envelope ArtifactStatus | Meaning |
| --- | --- | --- |
| PENDING / PARTIAL | CREATED, VALID, INVALID, SUPERSEDED, ARCHIVED | Record validation/history is independent; never a final business-consumable result |
| SUCCEEDED | CREATED, VALID, INVALID, SUPERSEDED, ARCHIVED | CREATED awaits validation; INVALID records consumer rejection without changing the captured producer outcome; historical states do not select current work |
| FAILED / CANCELLED / TIMEOUT | INVALID only | Immutable unsuccessful checkpoint, never a usable result |
| approved_snapshot / SUCCEEDED | VALID, SUPERSEDED, ARCHIVED only | Insert VALID in the human-authorized publication transaction, or read historical status; never persist a pending/failed “approved” snapshot |

Allowed ArtifactStatus transitions remain CREATED→VALID→SUPERSEDED or ARCHIVED; CREATED→INVALID. INVALID is terminal. A CREATED result rejected by consumer validation may become INVALID while its captured operationStatus stays SUCCEEDED. Emit a linked failure diagnostic for the rejection reason without changing that payload. A previously VALID result cannot flip to INVALID; supersede it with corrected work or preserve it and append a failure diagnostic. A structurally accepted PENDING/PARTIAL checkpoint may be VALID and later superseded/archived; it still cannot advance the pipeline as final success. Payloads never mutate, even in CREATED. Changing operationStatus PENDING→SUCCEEDED means a **new artifact ID**, not updating the checkpoint. An invalid wire payload rejected before persistence is not stored wholesale as an INVALID artifact; return the safe API error and, where authorized identity/ownership is known, emit a schema-valid failure variant instead.

All 16 variants and every allowed stage/outcome combination are enumerated by registry.json and tested. Exceptions: `approved_snapshot`, `candidate_decision`, `manual_commit` allow SUCCEEDED only; `publication_attempt` allows PENDING/PARTIAL/FAILED/CANCELLED/TIMEOUT only. A successful attempt is represented by its terminal decision/commit and approved snapshot, not a second mutable success ledger. There is no ERROR ArtifactType and no workflow/agent/preference-memory type added.

Only VALID + SUCCEEDED **final variants** may be consumed at the corresponding boundary: intake→Reader; structured_document→Extraction; extraction→governance; context→Prompt Builder; prompt→provider execution; response→Message completion. An eligible governance result still pauses for human review. A VALID candidate_decision, including REJECT, is audit data, never approved context. Historical SUPERSEDED/ARCHIVED approved snapshots remain inspectable under authorization; selecting/restoring them follows provenance rules and cannot silently make them current generation input.

## Stage and result contracts

The exact lower_snake_case `producingStage` registry values replace illustrative class names. A pipeline configuration may select/reorder supported processing stages; adding a new stage requires a registered schema release, not an arbitrary string. Nine document stages produce eight intermediate checkpoint families and final Quality Validator output; Quality Validator emits STRUCTURED_DOCUMENT, including its unsuccessful checkpoints, without a duplicate ninth intermediate.

| Producer / variant | Registered stages | Result / common definitions |
| --- | --- | --- |
| INGESTION / intake | intake | source descriptor + stored-object key/digest/byte length/MIME and validation. Successful intake requires a non-null object reference and passed validation. sourceId is a logical source identity, not a promise that a Document exists after rejected intake. |
| DOCUMENT_PROCESSING / processing_stage | reader, cleaner, normalizer, language_detector, metadata_extractor, structure_analyzer, chunk_generator, chunk_optimizer | Closed processing fragment. SUCCEEDED additionally requires cleanText, language, metadata, structure or chunks appropriate to that stage (enforced by envelope conditions). |
| DOCUMENT_PROCESSING / structured_document | quality_validator | Complete cleanText/documentStructure/metadata/chunks/language/processingMetadata on success. Chunk includes actual text and normalized sourceOffset, source location availability, parent Document/section, sequence and counts. parentDocumentId is a Document UUID, not the final Artifact UUID. |
| KNOWLEDGE_EXTRACTION / extraction_stage | information_extraction, entity_normalization, semantic_interpretation, entity_classification, relationship_builder | Closed extraction fragment; no approved facts or arbitrary semantic labels. |
| KNOWLEDGE_EXTRACTION / extraction | candidate_builder | ontologyVersion, candidateEntities, candidateItems, candidateRelationships, provenance and extractionConfidence. Item holds stable candidateId, typed change/baseRevisionId/trigger/eligibility/flags/time. Extraction items are IMPORT/SET/IMPORTED, NOT_EVALUATED and PENDING_REVIEW; cannot invent manual-only facts, approval or verification. |
| KNOWLEDGE_MANAGEMENT / governance_stage | schema_validation, business_rule_validation, ontology_validation, duplicate_detection, conflict_detection, knowledge_merge, knowledge_confidence_calculation, policy_engine | References original candidate artifact, eligible/ineligible item IDs/reasons, flags, policyVersion and measured-or-unknown confidence/trust. | KNOWLEDGE_MANAGEMENT / candidate_decision | candidate_decision | Original candidate Artifact/item, CONFIRM/EDIT_AND_CONFIRM/REJECT, actor/time/reason, expected head, operation/idempotency/request hashes, changed proposal if edited, result revision when published. CONFIRM/REJECT have no edited changes; edit requires changes and reason. Exactly one terminal item decision under Brand lock. |
| KNOWLEDGE_MANAGEMENT / manual_commit | manual_commit | INITIALIZE/MANUAL_EDIT/VERIFY/RESTORE, actor/time/reason, expected/result revision, hashes, changes/verified keys/restored revision as applicable. No candidate/source/extraction identity invented. |
| KNOWLEDGE_MANAGEMENT / publication_attempt | publication_attempt | Expected head, optional candidate references, operation/request hash; no approval or successful result. Failure/timeout/cancellation describes an uncommitted attempt, not erasure of a previous approved revision. |
| KNOWLEDGE_MANAGEMENT / approved_snapshot | publish_snapshot | Full revisionId/ontologyVersion manifest, members, typed facts, representative calculation selection and removals/change kind. Values and field provenance only here; approval/completeness/order remain BrandBrainRevision metadata. |
| CONTEXT_ENGINE / context_stage | intent_analyzer, retrieval_planner, knowledge_retrieval, context_ranking, business_rule_injection, brand_voice_injection, memory_selection, context_compression | Closed context fragment; intent/required entity state uses WORKING memory object. No new Context Artifact type. |
| CONTEXT_ENGINE / context | context_validation | assemblyVersion/retrievalStrategy/contextProfile, selected fact refs, rule fact refs, Voice fact refs, permitted memory, evidence, pinned approved revision/artifact and contextScore indicator. Full data only at success. |
| AI_ORCHESTRATOR / prompt_stage | capability_detection, capability_resolution, execution_planning, context_request, model_selection, tool_resolution | Closed planning fragment; known capability/template/context/model metadata. | AI_ORCHESTRATOR / prompt | prompt_builder | Actual messages plus template/prompt/capability/context versions and IDs, pinned revision, provider-neutral modelConfiguration. `tools=[]` in MVP. Raw source facts remain data, never model-created system authority. |
| AI_ORCHESTRATOR / response_stage | llm_execution | Closed response fragment; partial provider text is operational data, not completed user history or trusted knowledge. |
| AI_ORCHESTRATOR / response | response_validation | Full generatedResponse, prompt/revision refs, modelProvider/modelName, tokenUsage, latency, estimatedCost, passed validation on success. Failed validation cannot masquerade as a final successful answer. |

Knowledge fact keys use exact KnowledgeEntityType strings. DOCUMENT is a structural reference/member kind, not a material fact-value namespace; business fact schemas cover ORGANIZATION, BRAND, BRAND_VOICE, PRODUCT, SERVICE, AUDIENCE, COMPETITOR. Only ontology fields are allowed with typed non-null values; reviewed removal is a REMOVE change, omitted from the new snapshot and recorded in changes, not approved null. Manual-only field rules and 2–4 distinct manual tones are enforced by the fact/change schema. Industry/Tone/PrimaryGoal values match Prisma; CompanySize/Region/Language are nonempty strings pending D-AUD-03 vocabulary resolution, not an invented locked enum.

`candidateRelationships` is a typed proposal DTO with relationshipType/source/target/evidence. Endpoints discriminate ENTITY (typed entity ref) or CANDIDATE (stable item ID for the logical Knowledge wrapper), using HAS/TARGETS/USES/PRODUCES/ORIGINATES_FROM/MAY_DESCRIBE/COMPETES_WITH. Ontology source/target/cardinality validation is still required. It is not a persisted approved graph implementation: D-AUD-06 still owns graph/lifecycle projection and reconstruction. Empty proposal lists are valid; reserved Campaign/Persona/Content/Asset/Channel types and illustrative Solves/Consumes labels are not legal MVP entity/relationship enum values.

Fact provenance includes origin, actual evidence or MANUAL author/time or documented DERIVED lineage, explicit itemProvenance and revision links. Mixed-origin lists remain one typed value with stable item IDs/index provenance; server checks exact index coverage/uniqueness. A manual merge has MANUAL field origin plus retained individual origins; manual-only lists cannot contain imported/derived items. DERIVED is a supported provenance representation requiring an existing scoped rule and explicit Owner approval, not authority for automated inference/interaction mining. Unknown confidence is `{value:null,basis:null}`; a known number requires a nonempty basis. No formula or provider is selected by the schema.

## Manual initialization and publication

1. Signup/setup may create the permitted draft Organization/Brand skeleton. No approved head, fake facts, synthetic User Input ArtifactType, source Document, intake or extraction job is required. Invalid requests before an authorized Brand exists use a normal API error, not fabricated artifacts.
2. Explicit initial save validates manual facts, current Owner, expectedRevisionId=null and idempotency. Preallocate commit Artifact, approved Artifact and BrandBrainRevision UUIDs. Manual `changes` record the reviewed diff; no abandoned draft is persisted by implication.
3. In one short Brand-locked transaction insert KNOWLEDGE_CANDIDATE/manual_commit, parent=null, operationStatus=SUCCEEDED, status=VALID. It has real actor/time, resultingRevisionId, hashes and reason. Insert APPROVED_KNOWLEDGE/approved_snapshot, parent=commit Artifact, same mutation correlationId, with facts pointing at that preallocated revision; insert BrandBrainRevision and advance projections/head atomically. A partial but valid Brain may be approved with readiness=false; the schema does not require all mandatory generation facts to exist before an initial save. An explicit later clear may produce zero current facts with removal metadata and readiness=false; never fabricate replacement facts or mistake a real cleared revision for a no-head display placeholder.
4. Later manual edits/verify/restore use the same commit variant with parent=the previous approved snapshot; expectedRevisionId must match that snapshot’s revision. This parent may have an earlier operation correlationId. Restoring appends a new reviewed revision, preserving old verification links; it is not pointer rewind or a new extraction job.
5. Before a successful transaction there is **no persisted successful commit or approved snapshot**. Rollback removes both. A subsequent authorized failure diagnostic uses KNOWLEDGE_CANDIDATE/publication_attempt and preserves the old head; pending/partial work cannot approve. Deletion suppresses late generation diagnostics except the narrowly permitted internal cleanup bookkeeping in DATA_LIFECYCLE.md.

Import confirmation is a parallel path: candidate_decision parent points to the original candidate Artifact, with item identity; approved snapshot parent points to that successful decision and result revision. All item decision artifacts retain the import correlationId; operationId distinguishes individual user decisions and provider/worker attempts retain their operation’s correlation. Whole-import admission/closure remains D-AUD-07/R23; schemas do not infer it from the latest artifact.

## References, authorization and non-schema invariants

JSON Schema verifies shape, formats and allowed combinations, not row existence, authorization or cross-row equality. The server must load actual records under validated principal/tenant context, coordinate locks with cleanup, then perform these checks before persistence/consumption:

- Envelope organization/Brand and every parent, Conversation, Document, Artifact, entity, candidate, revision and author/actor reference belong to the same authorized tenant and appropriate Brand. Global User identity requires a current joined Owner membership, not a fictional User.organizationId column. Use non-disclosing 404 for inaccessible objects.
- Generation artifacts require conversationId; import/knowledge artifacts require null. Source/approved knowledge may never acquire conversation ownership. Referenced generation parents/context/prompt must belong to the same Conversation; check deletedAt on acceptance, reads and before publication/streaming. Internal system identity alone is not knowledge approval.
- Match reference types: source Artifact RAW_INTAKE/STRUCTURED_DOCUMENT, candidate Artifact KNOWLEDGE_CANDIDATE, prompt/context/approved Artifact exact corresponding type. Evidence requires an actual Document tied to that source lineage/correlation; chunk IDs must occur in that captured source for that Document. Hash/byte length and section/range ordering must be verified against stored data. Source objects are tenant-bound keys, never arbitrary URLs to fetch.
- Check snapshot member/fact-key uniqueness, entity membership/type, actual ontology constraints, manual-only origins, list item IDs/indices, source/derivation cycles and referenced field existence. Current snapshot data.revisionId, revision.artifactId and ontologyVersion must agree; field introducing/superseding/verification revisions must be same Brand, valid and not impossible future lineage. BrandBrainRevision owns approver/time/score/readiness; these are not user-writable snapshot fields.
- Check snapshot parent is its matching terminal manual/item commit and resultingRevisionId; item decision parent/item must match the original candidate and actual eligibility. Reject leaves head unchanged; edit revalidates and preserves original reference. CONFIRM uses the original approved proposal value, not a client-supplied replacement. No worker can invent Owner approval metadata.
- Generation context pins a compatible current approved revision and complete members under readiness; every fact/Voice/rule ref belongs to that pinned revision. Prompt contextVersion must match assemblyVersion; response promptVersion and pinned revision/provider/model must match the actual execution. These are consistency checks, not permission to mix old/new head data or choose a provider. D-AUD-01/02/03, D-SEC and operational budgets stay open.

[Offline reference checker](../../validation/artifact_reference_checks.cjs) exercises a subset of these checks against synthetic lookup records. It is **not** a production authorization gateway or exhaustive ontology/reference validator. Real database locking, acyclicity/eligibility/head checks, projection transactions and deletion/backup behavior still require application integration tests and review. [Provenance](../../KNOWLEDGE_PROVENANCE.md) remains normative for reference-aware retention: historical JSON references protect source identity; byte expiry does not silently invalidate UUIDs or authorize cascade erasure.

## Idempotency and errors

Allocate correlationId at an accepted import, manual mutation or assistant attempt entry. It is tracing identity, never an authorization token, deletion selector or idempotency key. Internal retries retain it; explicit retry after a terminal assistant Message gets a new Message/correlationId. Never mutate a terminal attempt to restart it. Pre-authorization rejection may have a content-free request diagnostic without an Artifact.

A stage invocation has stable invocationId; internal retries increment 1-based attemptNumber (legacy retryCount=attemptNumber−1). Within that invocation/attempt, checkpointNumber starts at0 and increases for PENDING/PARTIAL/result checkpoints; redelivery reuses the allocated Artifact ID and checkpoint tuple, never invents a second event. The worker fences emissions for the same tuple; these fields order stage-local checkpoints, not whole-import UX closure. A failed intermediate invocation may be retried within budget; it is not automatically a terminal Message. The Orchestrator alone decides when a final outcome terminates its Message under the existing lifecycle.

Scope idempotency lookup by Organization + Brand + actor + operation kind + SHA-256(Idempotency-Key UTF-8). Persist only key hash and requestHash in immutable terminal commit/decision JSON. Request hash uses `stable-json-v1`: schema-validated normalized JSON DTO `{method,target,body}`, recursively lexicographically sorted object keys, preserved array order, JSON.stringify primitive encoding, UTF-8 SHA-256; target identifies canonical resource/action. No undefined, BigInt, NaN or unsafe-number coercions; textual money stays string. This is a project encoding, not a claim of RFC8785 conformance. Scope values are server-derived and not changed on retry. [Reference helper](../../validation/artifact_compatibility.cjs) tests ordering/replay/conflict behavior.

Under Brand lock: same scope/key + same requestHash → replay original result; same key/different hash → 409 CONFLICT; a second operation deciding an already terminal item → 409; a changed expected head → 409 and fresh review. Rollback leaves no successful key record. In-flight queue delivery must use reviewed lease/fencing and reconcile committed artifacts before retrying. PostgreSQL JSON lookup/indexes plus serialized handlers are specified; no unique JSON key constraint or new job table is claimed. Response fields requiring current head may be re-expanded but must identify the original resultingRevisionId and operation replay; never create another approval.

Failure data has a bounded safe message, exact code, retryable, optional retryAfterMs, violationPaths and diagnosticId. Codes are INPUT_INVALID, UNSUPPORTED_FORMAT, RESOURCE_LIMIT, SOURCE_UNAVAILABLE, SOURCE_UNSAFE, PARSER_FAILED, CONTRACT_INVALID, REFERENCE_INVALID, ONTOLOGY_INVALID, CONFLICT, POLICY_DENIED, CONTEXT_UNAVAILABLE, PROVIDER_FAILED, OUTPUT_INVALID, INTERNAL_ERROR, CANCELLED, TIMEOUT. CANCELLED/TIMEOUT outcomes require their matching code. No provider bodies, source excerpts, secrets or stack traces in error metadata/telemetry; diagnostic fragments themselves remain protected Artifact content. Retryable means eligible under reviewed budgets, not unbounded retry or permission to retry a terminal Message in place.

API adapters retain `{success:false,error:{code,message}}` and content-free correlation reference; full internal artifact envelopes are not public error bodies. Map invalid shape/version/origin/ontology to 422, stale head/idempotency/prior decision to 409, inaccessible references to non-disclosing404, infrastructure failure to503 or safe stream failure. Auth failures keep the auth contract. Trusted internal cancellation/timeout maps the existing per-message lifecycle; schemas add no public cancel endpoint or new timeout duration. Unknown schema versions fail CONTRACT_INVALID with safe reason; never retry endlessly or guess a schema.

## Serialization aliases and compatibility

Version2.0.0 is the first fully specified schema set; 1.0.0 drafts were field inventories, not a machine-readable compatibility guarantee. Envelope schemaVersion selects **exact registered schema**, not any string with matching major version. All eight payload schemas share this bundle version to prevent mixed common-definition revisions. New writes use 2.0.0 only after Architecture/Engineering review and rollout. Unknown versions cannot be written, regenerated as current, approved, indexed for generation or routed to a provider.

| Historical label / ambiguity | Canonical v2 encoding / reading rule |
| --- | --- |
| ORM id / artifactId / Response ID / Prompt ID | Envelope artifactId=Prisma Artifact.id; candidateId is a distinct item UUID inside candidateItems; data.revisionId is the matched revision manifest |
| Created / Valid / Invalid / Superseded / Archived | Exact uppercase ArtifactStatus; title case recognized only in the legacy header classifier, never accepted by v2 writers |
| Ingestion / DocumentProcessing / etc. | Exact ProducingService enum via explicit ORM serialization; displayed service names are labels |
| Reader / Language Detector / PromptBuilder | Exact producingStage registry strings; no class-name guessing in current writers |
| intakeStatus / processingStatus / extractionStatus / contextAssemblyStatus / executionStatus | One payload.operationStatus enum, with typed variant/data. Document.processingStatus and MessageStatus remain separate. Unknown old outcome labels are not guessed from ArtifactStatus. |
| payload fields directly on old payload | v2 payload.data contains result fields; variant/operationStatus/brandId and applicable source identity stay on payload. This is an explicit major serialization change, not a mutation of old records. |
| file / url versus DocumentSourceType | Intake sourceType stays file/url; explicit adapter maps file→UPLOAD and url→URL for Document. No new DocumentSourceType. |
| BrandVoice / Product / BusinessProfile / Offering / Knowledge | KnowledgeEntityType uses BRAND_VOICE/PRODUCT/etc.; BusinessProfile and Offering are explanatory aliases, never persisted entity types; Knowledge is the governed wrapper, not a recursive fact entity type |
| Model Version / Provider / Execution Time / Cost | data.modelProvider registry key + modelName, latency in milliseconds, estimatedCost={amount:decimal string,currency:ISO currency code} or null. Configured provider allowlist still required; fixture is not a selected provider. |
| resultRevisionId / actorId / author/time / source/both | resultingRevisionId on decision/commit; actorUserId; manual.authorUserId/authoredAt; field MANUAL/IMPORTED/DERIVED. No fabricated evidence or BOTH origin. |
| Source Offset / Parent Document / ontologyVersion header | Chunk sourceOffset is normalized text offset; parentDocumentId is Document.id; ontologyVersion belongs to relevant result data and matches revision metadata, not an extra envelope field |

Historical reading is version-routed after tenant authorization. A genuine existing reviewed v1 decoder, if available in application code, may continue for its approved scope while migration is staged; none is claimed implemented by this repo. The supplied [compatibility helper](../../validation/artifact_compatibility.cjs) demonstrates a conservative **LEGACY_OPAQUE** mode for 1.0.0 headers (including exact title-case status aliases), not fabricated full conversion. Preserve original bytes/payload and approval history. Show authorized historical identity/unsupported-format explanation; do not invent required facts, provenance, status outcomes or readiness. Unsupported legacy structure goes to LEGACY_QUARANTINE for repair, not a new persisted ArtifactStatus. Unknown versions are UNSUPPORTED_VERSION. Compatibility classifications are reader results, never database states or automatic downgrade of a recorded historical approval.

Tests exercise strict v2 rejection, legacy title-case recognition/read-only ineligibility, unknown version handling, hashes and offline reference failures. No fixture asserts that arbitrary v1 payloads become current merely by changing schemaVersion. An unsupported current head blocks generation until a reviewed reader/migration or explicit Owner-approved reevaluation is available; it does not silently revoke business approval or replace that head.

## Migration and review requirements

No Prisma changes or DDL migration are necessary: existing Artifact JSON, string schemaVersion/producingStage, enums and BrandBrainRevision relations suffice. No ExportJob, Document for manual input, extraction job table, error enum/model, alternate approval store or new memory capability is introduced. JSON writer/reader changes are a **data-contract migration**, even without DDL.

1. Inventory actual stored versions/aliases, invalid/missing tenant/source/candidate/revision metadata, current approved heads and all consumers. Do not assume this docs repository proves a running implementation or extant v1 decoder.
2. Review D-AUD-04 with Architecture/Engineering and producing service owners. Capture actual approving identity/revision/date; no auto-approval from a passing test. Resolve dependent policies/interfaces before enabling their paths.
3. Register schemas locally, deploy dual readers before new writers, fixture-test deterministic mappings, validate references and output gates. Keep original immutable records unchanged; use adapters or explicit append-only migration records/approved revisions rather than in-place schemaVersion relabeling.
4. Backfill only mechanically provable identity/type/location references, preserving unknowns. Missing approval/provenance needs Owner re-review, not fabricated data. Rebuild projections only from a verified head/snapshot pair; never upgrade extraction to approved knowledge.
5. Enable v2 writers after reviewed compatibility/recovery tests, metric event versioning and reference/retention controls. Rollback disables v2 writes and keeps the v2 reader/history and all published revisions; never route v2 into an incompatible old decoder or rewind a head to erase changes.
6. Additive fields/stages/status outcomes require a new minor bundle and explicit reader registration; closed schemas do not automatically accept them. Breaking rename/type/meaning changes require a new major. Patch fixes must not reinterpret persisted meaning. Versions/directories/URNs are immutable once adopted; pin the Git revision/digests in release evidence.

Remaining owners: Architecture/Engineering review of this proposed serialization and lifecycle matrix (D-AUD-04); Product/Architecture confidence/vocabulary policy D-AUD-03; source mapping D-AUD-05; relationship/lifecycle projections D-AUD-06; import closure/admission D-AUD-07/D-IMP; history/provider routes D-AUD-01/02; API transport D-AUD-08; Security/Operations runtime limits, disclosure and retention.
