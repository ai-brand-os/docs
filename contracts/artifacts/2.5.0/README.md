# Proposed Artifact2.5.0 — conversation acceptance and selected history

**Proposed — Pending Architecture/Engineering/Security Review D-HIST-04.** [ADR-016](../../../domain/15_CONVERSATION_CONTEXT_AND_HISTORY_ADR.md), [history1.0 contracts](../../conversation-context/README.md), [registry](registry.json), [examples](examples/valid.json). No new ArtifactType/role/MessageStatus or in-place older schema change.

[history_request](history_request.schema.json): exact PROMPT / AI_ORCHESTRATOR / history_acceptance, status VALID, operationStatus SUCCEEDED/error=null. Success means **acceptance receipt persisted**, not model execution, generated response, approval or Message completion. Workspace boundary authorizes and owns acceptance; its Orchestrator module provider emits the receipt in the same database transaction. No additional Workspace producer enum. Root conversationId is mandatory; tenant/Brand/current USER/ASSISTANT/correlation/revision and all references must match actual stored records. Parent is the pinned approved Artifact. Request metadata is defined once by history1.0; no raw transcript/current text copied into this receipt.

[context](context.schema.json): exact PROMPT_CONTEXT / CONTEXT_ENGINE / context, VALID/SUCCEEDED only. Reuses2.3 final context properties unchanged via exact schema refs and adds conversationHistory selection. Its parent is this attempt's history_request Artifact; approved knowledge is explicit in provenance. Selection scope/current IDs/cutoff/catalog/policy/revision must match receipt; included Message hashes resolve against immutable authorized source rows. selectedKnowledge/selectedRelationships, context provenance, Prompt and Response revision all agree. Empty selectedRelationships is valid when the separately reviewed relationship feature is inactive. contextScore stays null/null while D-KQ formulas remain disabled.

Pending/partial/failure/cancel/timeout use existing operation checkpoints/errors; these new variants are successful receipt/context only. Failed acceptance transaction leaves no successful receipt/USER/placeholder. Missing source/context returns existing safe API/domain failure mapping; internal fixture reasons are not new Artifact/Gateway error enum aliases. New receipt/context artifacts are conversation-owned purge inventory, not imported business evidence or import lifecycle events.

Final PROMPT/RESPONSE remain2.0: existing contextArtifactId, approvedRevisionId, actual messages and response→prompt refs suffice. [Final2.0 fixture](examples/final-2.0.json) demonstrates the exact SYSTEM/USER-data wire with no new provider/Gateway role. Follow RESPONSE→PROMPT→context→receipt for selection audit; references deny after deletion/purge. Existing final raw prompt/response duplication is covered by conversation retention; no extra persisted transcript/summary.

New acceptance dedupe is authenticated tenant/Conversation/actor/operation/key with canonical body hash and serialized row lock; changed body conflicts, same request returns original receipt/pin after live reauthorization. Context must recompute selection/hash/budget under pinned policy and match receipt/current sources before use. JSON refs are application invariants, not existing Prisma FKs. Exact physical order/association DDL is separately proposed; do not claim migration executed.

Reader-first version dispatch supports old contexts as HISTORY_NOT_RECORDED and cannot fabricate old cutoffs. Historic old prompts remain accessible only under normal authorization/retention, not a history reconstruction loophole. Rollback disables new acceptance and keeps2.5/order readers; no stripping/resequencing/downgrade. Unknown versions fail closed. D-HIST-01/02/03/04, D-GW-01, D-AUD-08 and retention/security/quality gates remain pending; no runtime/coherence/provider outcome is established by fixtures.
