# Proposed Artifact2.2 evidence attachments

Status: **Proposed — Pending Architecture/Engineering Review (D-EVID-01)**, 2026-10-18. [ADR-013](../../../domain/12_SOURCE_EVIDENCE_MAPPING_ADR.md) and [source-evidence contracts](../../source-evidence/README.md) define semantics, mapping, historical binding and rollout. This is not an approved schema migration or active writer.

[Registry](registry.json) adds only two JSON attachment variants with existing enums/table: PROCESSING_INTERMEDIATE/representation_manifest (DOCUMENT_PROCESSING/evidence_manifest) and KNOWLEDGE_CANDIDATE/evidence_binding (KNOWLEDGE_MANAGEMENT/evidence_validation). Wrappers reference the canonical source-evidence1.0.0 manifest/binding schemas. Existing Artifact2.0, proposed import-control2.1, Gateway1.0 and Prisma are unchanged. They are read by exact-version dispatch, never relabeled or loosened.

Attachments are validated reference dependencies of existing selected pipeline/candidate records. They are not import-control events, public statuses, new knowledge/approval stores or fields smuggled into old payloads. Require reader-before-writer rollout and unique immutable original-candidate binding under shared reference locks; historical lookup follows introducing decision/revision lineage. Unknown/missing legacy mapping is unavailable, not invented. Rollback retains mixed readers and all historical identity; no deletion/rewrite of previously approved provenance. [Results and limits](../../../validation/TASK19_RESULTS.md) distinguish conformance from actual parser/storage/security/transaction integration.
