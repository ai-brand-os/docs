# Proposed Artifact 2.3.0 — approved relationships

**Proposed — Pending Architecture/Engineering Review (D-REL-01)**. This amendment is separate from unchanged Artifact2.0/2.1/2.2 and [Source Evidence1.0](../../source-evidence/README.md). [ADR-014](../../../domain/13_ONTOLOGY_RELATIONSHIP_PERSISTENCE_ADR.md) and [relationship contracts](../../ontology-relations/README.md) define semantic constraints. No new Prisma model, enum or independently authoritative graph store.

[Registry](registry.json) enumerates exactly three successful final variants: [APPROVED_KNOWLEDGE/approved_snapshot](approved_snapshot.schema.json), [KNOWLEDGE_CANDIDATE/relationship_commit](relationship_commit.schema.json), [PROMPT_CONTEXT/context](context.schema.json). All status=VALID, operationStatus=SUCCEEDED, error=null. Snapshot stage remains publish_snapshot. Operational pending/partial/failed/cancelled/timeout checkpoints and errors retain their existing 2.0 variants; a failed approval transaction creates no successful relationship commit. No new error aliases are admitted into old enums. Pure relationship mutation request errors use the existing API contract, not invented pipeline events.

Existing envelope correlation/invocation/attempt fields retain their meanings. APPROVED_KNOWLEDGE data keeps members, facts, calculationSelection, changes, revisionId and ontologyVersion at existing paths, adding relationships. Members/facts are canonical, not copied into a second graph snapshot. Graph tenant is inherited; per-edge scope and graph revision must match enclosing metadata. Snapshot parent points to sole applicable approval commit; unchanged edges may retain earlier approvals. Relationship-only commits contain reviewed delta IDs/dispositions and receipt metadata, never duplicate full edge values. Field-only and imported fact commits continue to use existing variants. Existing removal/restore previews must include incident-edge consequences; do not generate a redundant second decision for the same operation.

PROMPT_CONTEXT keeps existing context fields and adds selectedRelationships plus relationshipSelection (truncated/reason). Every selected explicit edge must resolve in its single pinned snapshot. A derived USES ref uses the deterministic tuple ID and exact rule version; it may not claim an explicit approval edge. Empty selectedRelationships is valid when no reviewed relationship applies. With truncated=false reason must be null; with true it identifies EDGE_LIMIT or NODE_LIMIT. Runtime semantic checks enforce that consistency and exact context provenance revision. Fact-based structural/provenance views remain existing selectedKnowledge/evidence and do not invent fake edge facts.

Reader routing uses exact schemaVersion and payload.variant; old readers reject 2.3. New readers must support historical versions without reinterpretation. Historical v2 missing graph means NOT_RECORDED, never known empty. New ontology1.2/registry1.0 writes require D-REL-01/02 review and a reviewed baseline; no speculative migration/backfill. Reader-first rollout, legal retained identity inventory and real cross-record transaction tests precede writers. Rollback disables writers, retains readers or denies affected workflows; never downgrade by dropping relationships. No SQL migration is needed. [Examples](examples/valid.json) are synthetic; the offline test runner loads all dependencies locally without network. Adoption and runtime implementation remain unverified.
