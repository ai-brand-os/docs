## Request and ordering

Actual Workspace repository authorizes tenant/Brand/Conversation and actor. Under short Conversation/Brand locks, allocate monotonic positive BIGINT USER/ASSISTANT slots, link assistant to actual user, capture ready approved revision, accept body/key and persist request receipt/rows atomically. JSON sequence is a canonical decimal string, never a floating number; cutoff=currentUserSequence−1 can be0. Reference algorithm models success-only state mutation; it is not a transaction implementation. Actual writers must check ID uniqueness, sequence exhaustion, scope/role/ref integrity and canonical receipt uniqueness before committing.

Request fields are closed and required. Null originalRequestArtifactId is for NEW only; TERMINAL_RETRY/REGENERATE must reference an authorized earlier receipt in this Conversation. Current user content SHA binds immutable accepted text; the USER is absent from history and serialized exactly once. Freeze bounded prior-row status, sequence, reply ID, final-response reference/revision and content digest at capture. Completed content has digest; excluded pending/failed content need not be copied or hashed. CatalogHash is stable-json-v1/SHA256 of scope+cutoff+history; requestHash is SHA256/stable-json-v1 of caller action/body/scope/kind/original request, excluding server-resolved changing head and generated IDs. policyDigest hashes the whole reviewed immutable policy. Idempotency key hash hashes its exact UTF8 bytes. Hashes detect inconsistency, not authorization/authenticity.

Reader loads recent finite whole USER turns with bounded attempt fanout below cutoff, ordered by immutable sequence. maxCandidateTurns/maxCandidateMessages/maxCandidateBytes are reviewed policy, not deployment defaults. scanLowerSequence and olderPrefixOmitted identify unscanned prefix; no false claim full history was inspected. Pagination follows the frozen receipt's sequence/key/hash, not live time/OFFSET. Stored byte lengths must be checked before body fetch/hash; exceeding total loader bytes/attempt fanout fails HISTORY_SCAN_LIMIT without acceptance, not an unbounded scan. Within loader bounds, large messages still use the whole-turn token rule. Same timestamp/creation UUID order cannot fabricate a legacy timeline; legacy unsequenced history is not reproducible and remains LEGACY_UNORDERED until explicit reviewed baseline/migration. Older v2 artifacts without fields report HISTORY_NOT_RECORDED, not known-empty.

## Eligibility and selection

Only committed accessible same-Conversation USER(COMPLETED) and validated final ASSISTANT(COMPLETED) qualify. Exclude failed/cancelled/timeout/queued/generating/partial/unsupported/internal/uncommitted/newer rows. Greatest successful assistant slot at capture wins for a user; other attempts have explicit exclusion reasons. An unanswered user after assistant failure remains a whole USER-only historical turn, subject to Product review. A response completing after catalog capture never enters that request, even if its reserved slot is below cutoff. Current access/tombstone/content hash/final response checks still apply; missing/changed selected reference fails rather than rereading another text version or a deleted artifact.

Select newest whole turn, extend backward until first whole turn will not fit; stop there, do not skip to older small turns, summarize or partially truncate. Keep selected suffix chronological. Exclusion metadata contains bounded candidate Message IDs/reasons, selected turn IDs, cutoff/catalog/revision/request refs and budget usage; no raw text. Private wireSha256 binds the exact serialized final existing-role prompt messages; final PROMPT and Gateway request must reproduce it under the pinned template. A true first turn has empty history normally. Nonempty candidate history fitting zero turns requires explicitly reviewed currentOnlyAllowed and currentOnly limitation metadata; otherwise HISTORY_REQUIRED. Client fallback disclosure/shorter-input flow remains D-AUD-08, not an unannounced generic response. Production fallback permission defaults unapproved, not true.

## Budgets, tokenizer and exact wire

Reviewed policy supplies W(providerWindow), I(maxInput), T/U/K/H(partition caps), O(output), S(serialization) and R(safety). Require T+U+K+H+S≤I and T+U+K+H+S+O+R≤W. Exact actual serialized input independently must fit I and W−O−R. Mandatory trusted/current/approved data cannot be shortened to fit. Oversized current input or mandatory business context fails safely; large prior pasted documents are dropped only as whole turns under disclosed history policy. No character-to-token ratio is a production default. Meter must be exact for pinned model/tokenizer/template/serializer or a reviewed proven upper bound; uncertain/negative/nonfinite counts fail.

Test policy is a **synthetic UTF8-byte-per-token model** and fixture numbers only. Actual deployment tokenizer/model/serialization digests, caps and provider policy remain D-GW-01/D-HIST-02. The meter callback is trusted infrastructure, never user/model input. Component accounting and final wire include JSON escape/role costs; production must verify the adapter's actual model framing. Reserved output/safety is not reclaimable history space. No benchmark or measured latency/quality claim.

Final wire uses existing SYSTEM(registered trusted instructions) and USER(JSON data containing approvedContext/history/currentRequest/executionMetadata). Historic USER/ASSISTANT roles are data labels inside that USER object; no new provider role or hidden system prompt. JSON serialization prevents quote text from changing structure; server policy/provider/auth stay outside the data. Approved facts outrank old assistant claims under trusted instruction policy; no automatic semantic fact-checker or tool action. Gateway1 task.content carries the data string and loads trusted template instructions separately; it never fetches history or appends current message again. PROMPT2.0 already records the exact wire; current raw prompt duplication remains conversation-owned and purgeable. Real-provider injection resistance/coherence needs testing.

## Retry, pinning and privacy

Receipt/transport retry reuses accepted pin/catalog/policy/wire. Explicit terminal retry creates a new assistant/operation/correlation while reusing latest user's original catalog/revision; no new user row or terminal reset. Only the latest terminal assistant for the latest user may be retried; active sibling attempts or a stale earlier attempt reject before allocation. Conditional explicit regeneration after latest COMPLETED attempt selects current head and fresh catalog below the same latest user's cutoff; no old-turn branch/UI is enabled. Current readiness, revocation, archival, tombstone and policy guards can deny either path; never silently repin an accepted attempt. Source Messages remain immutable. A later head change does not mix facts/relationships across revisions.

SSE disconnect alone changes no MessageStatus; complete result may persist and be read under existing recovery contract. Duplicate callbacks cannot overwrite terminal result or duplicate completion. Conversation remains active after individual terminal outcomes. No new SSE replay/cancel endpoint is promised.

Reauthorize before egress, stream delivery and durable completion; delete/complete serialize on Conversation lock. Deletion denial beats reproducibility. Purge owns request/context/selection/prompt/response/retry artifacts, buffers and operational copies; no raw history in logs or backup rehydration for normal requests. Independent approved Brain remains. Actual provider/backup retention/deletion is separate D-SEC/D-POL review; no invented TTL or remote-erasure claim.

## Adoption, migration and rollback

D-HIST-01 reviews ordering columns/constraints/cutover; D-HIST-02 window/tokenizer/budgets/fallback; D-HIST-03 concurrency/retry/regeneration UX semantics; D-HIST-04 versioned receipts/ref integrity/retention/rollout. Earlier Artifact2.0–2.4/Gateway1/quality1/other bundles stay byte-identical. New Artifact2.5 readers and ordering-aware Prisma/client migration must precede writers only after approval. Exact DDL prototype validates mechanics, not legacy migration or application concurrency. Old-order data is never resequenced from timestamps/UUIDs. Rollback disables writers and retains metadata/order readers; do not strip history fields/drop columns or regenerate hidden summaries. D-KQ formulas remain disabled; no history score or auto-approval.
